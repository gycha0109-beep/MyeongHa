# D4B-8 — 손님 예약 비용의 권한 전환 후 정산

Watchtower-Track: character-memory

## 목적
손님 상태에서 예약한 AI 호출 비용을 같은 Subject가 회원으로 전환한 뒤 정산할 수 있는지, 응답 손실 재시도와 이용량 미확인 항목을 포함해 일회용 PostgreSQL에서 검증합니다.

- 신규 손님 호출은 전환 이후 차단되어야 합니다.
- 이전에 승인된 비용 예약은 Member 신원으로 정산·재시도할 수 있어야 합니다.
- 만료된 손님 토큰은 신규 인증이 거부되어야 하며 이를 우회해 정산하는 권한을 임의 생성하지 않습니다.
- 외부 AI 공급자 호출, 운영 계정, 운영 비용 정책은 변경하지 않습니다.

## 검사 내용

1. 손님 상태에서 정상 예약한 3,700 microUSD 비용은 동일한 정식 사용자 번호가 회원으로 전환된 뒤 회원 권한으로 300 microUSD로 정산되고, 재시도해도 두 번 차감하거나 환급하면 안 됩니다.
2. 회원 전환 이후 이전 손님 토큰으로 비용 예약을 다시 시도하면 거절해야 합니다.
3. 이미 정산 권한을 획득하고 시작한 손님 거래가 진행 중 유효기간을 넘더라도 기존 예약의 정산은 완료되어야 합니다. 다만 기한이 지난 손님 자격을 새 거래에서 다시 획득하는 것은 금지됩니다.
4. 별도 PostgreSQL 연결과 실제 거래 커밋을 사용하며 합성 가격·계정만 허용합니다.

## 명시적인 잔여 위험

- 손님 신원이 **이미 만료된 후** 독립 정산 작업자가 신규 연결에서 정산하는 경로는 검증하지 않았습니다. 만료된 손님 토큰의 권한을 되살리는 방식으로 해결해서는 안 되며, 별도 서버 소유 정산 작업의 신원·예약 소유 검증 계약이 필요합니다.
- 이 검사는 사용자에게 청구되는 결제 기능이 아니라 인공지능 비용 원장과 전역 지출 상한을 검사합니다.
- 운영 데이터베이스 권한 변경, 유료 AI 호출, 기존 프로덕션 활성화는 포함하지 않습니다.
