# D4B-7 — 손님 권한 유효기간 경계 시험

Watchtower-Track: character-memory

## 목적
손님 세션은 자격 확인 순간에는 유효하더라도, 인공지능 비용을 예약하기 전에 유효기간이 끝날 수 있습니다. 예약 시각에 **새로운 비용 지출 권한을 보유하고 있는지** 확인합니다.

## 재현
- 기존 대화 기록이 있는 합성 사용자 번호를 일회용 데이터베이스에서 손님으로 준비합니다.
- 손님 접속 유효기간을 현재 시각부터 2초로 설정합니다.
- 현재 전용 검증 함수를 거쳐 손님 신원을 확인한 후, 같은 거래 안에서 3초를 경과시킵니다.
- 그 후 비용 예약을 요청합니다.
- 성공한다면 `BLOCKER`로 실패 처리합니다. 예약과 기록이 모두 발생하지 않아야 합니다.

## 영향
기존 구조를 임의로 변경하지 않고 문제를 먼저 독립 검증합니다. 실제 서비스, 운영 데이터, 유료 추론 호출, 기존 마이그레이션 수정 없음.

## 한계
이 검사는 손님 자격의 **시간 경과 만료**를 다룹니다. 이미 통과한 회원 전환·손님 증빙 소모와의 경합 검사를 대체하지 않습니다. 오류를 확인하면 기존 손님-회원 직렬화 계약을 유지하는 별도 수정 후 전체 재검증이 필요합니다.

## 수정 방식

- 비용 예약 전용 손님 신원 확인에서 실제 손님 접속 기록 번호를 동일 거래에 묶습니다.
- 전역 예산 잠금 이후, 새 비용 예약을 승인하는 시점에 해당 손님 접속 기록의 만료 시각을 **실제 현재 시각으로 다시 확인**합니다.
- 손님 계정의 회원 전환 경합을 차단하는 기존 사용자→손님 접속 기록 잠금 순서는 유지합니다.
- 회원 비용 예약은 기존 경로를 사용하고, 손님 만료 후 비용 예약만 거부합니다.
- 기존 함수의 실행 권한 및 소유권을 유지하고, 과거 변경 기록은 수정하지 않습니다.

## 검증 조건

실제 데이터베이스 검증과 전체 기능 점검이 모두 성공하기 전에는 최종 반영하지 않습니다. 운영 권한이나 비용 한도는 변경하지 않습니다.
