# D4B-10H — 영수증 확보·정산·확인 응답 유실 3단계 실제 연결 검증

Watchtower-Track: character-memory

## 목표

기존 D4B-10G는 정산 트랜잭션의 확정 응답 유실을 실제 PostgreSQL에 연결된 TypeScript 작업자로 검증했습니다. 이번 검증은 **영수증 확보, 정산, 확인** 세 개의 독립된 데이터베이스 트랜잭션에서 각각 `COMMIT`은 성공했지만 프로그램이 응답을 받지 못하는 상황을 검사합니다. 사용자 요청 재전송이나 유료 AI 추론은 실행하지 않습니다.

## 합격 조건

- **영수증 확보 응답 유실:** DB에는 임대만 남고 정산은 시작되지 않아야 합니다. 기존 임대 만료 후 재확보·정산·확인을 한 번만 수행해야 합니다. 호출 당시 예약액 3,700을 재정산 없이 새 영수증으로 부풀려서는 안 됩니다.
- **정산 응답 유실:** DB 원장은 정산 완료, 영수증은 미확인 상태여야 합니다. 임대 만료 후 같은 영수증을 재확인할 때 다시 비용이 늘어나지 않아야 합니다.
- **확인 응답 유실:** DB에서는 이미 확인 완료되어 있으므로 새 작업자가 동일 영수증을 다시 받아서는 안 됩니다. 코드에서는 성공으로 착각하지 않고 응답 유실을 실패로 보고해야 합니다.
- **수량·예산:** 5개 합성 호출의 예약 점유액 18,500에서 정산 결과 4,900으로만 감소하고 모두 정확히 1건의 원장 정산 및 확인 상태로 남아야 합니다. 사용량 불명 1건은 승인 상한 3,700을 그대로 차지해야 합니다.

## 안전성 및 검증

`CI=true`, 격리 DB 이름 `myeongha_seyeon_d4b10g_test`, 테스트용 플래그가 모두 일치하는 상황에서만 검사를 실행합니다. 응답 유실은 진짜 DB 확정 이후 연결 계층에서 재현합니다. 임대 강제 만료는 폐기되는 격리 DB에서만 수행합니다.

서버 코드와 운영 스케줄은 변경하지 않습니다. 운영 DB 이동·마이그레이션·자격 증명·결제·유료 모델 사용을 전혀 수반하지 않습니다. 운영 차단 [#1887](https://github.com/gycha0109-beep/MyeongHa/issues/1887)은 유지됩니다.
