# D4B-5 — 비용 예약·정산 잠금 대기와 교착 검증

Watchtower-Track: character-memory

## 범위

- 실제 서비스가 아닌 `myeongha_seyeon_d4b5_test` 일회용 PostgreSQL 데이터베이스에서 독립 연결로 검증.
- 합성 회원, 오프라인 정책, 정산 상한 3,700 및 실제 비용 300을 사용.
- 제품 함수의 기존 잠금 순서: 전역 일일 예산 행 → 개인 Subject 행(예약) 또는 비용 원장 행(정산).
- 운영 정책·기존 이력·권한·실제 서비스 데이터는 수정하지 않음.

## 검증

1. 별도 세션이 전역 예산 행을 잠근 상태로 예약을 실행해, 잠금 대기 제한(900ms) 위반 `55P03` 확인. 예약 기록/예산의 부분 변경이 없어야 하며 잠금 해제 후 동일 호출 ID로 정상 예약(3,700)되어야 함.
2. 별도 세션이 같은 예산 행을 잠근 상태로 정산을 실행해, 명령 실행 제한(900ms) 위반 `57014` 확인. 잠금 해제 전 3,700 유지, 이후 정상 정산으로 기록과 전역 점유가 함께 300이어야 함.
3. **합성 전용 관리자 세션**에서 실제 제품 규약과 정반대인 잠금 순서(개인 행 → 전역 예산 행)를 의도적으로 구성. 제품 예약 세션은 규약대로 전역 예산을 잡은 뒤 개인 행에서 기다리는지 `pg_blocking_pids`로 관측하고, 관리자 세션이 역방향으로 전역 예산을 요청해 실교착을 유발.
4. 데이터베이스가 교착 상태 `40P01`을 탐지해 두 작업 중 한쪽만 중단하며, 중단된 작업이 원장/예산을 절반만 기록하지 않았는지 검사. 예약 쪽이 중단되었다면 동일 호출 ID를 재사용해 안전하게 복구.
5. 이후 원장 2건의 실제 점유 합계와 전역 예산 점유 모두 4,000(300+3,700). 살아 있는 잠금 대기 없음.

## 주의 및 잔여 범위

- 의도적 역순 잠금 세션은 **운영에서 허용하는 실행 경로가 아니며**, 유일한 목적은 교착 탐지와 트랜잭션 롤백 검증임. 이것으로 제품 로직에 실교착이 발생한다고 주장할 수 없음.
- 실제 동시 다중 Subject/계정 삭제/정산 경합의 기존 검증을 보존. 손님 계정 승격과 토큰 만료 경쟁은 별도 미검증.
- 데이터베이스 대기 초과·교착 검증은 운영환경의 모든 장기 지연 가능성을 제거하지 않음. Production 전환, 외부 요금 청구 또는 실제 서비스 권한 교체를 승인하지 않음.
