# 세연 C09 — 대화 내 판단 연속성 Shadow 연결 v1

Watchtower-Track: `character-memory`
상태: **오프라인 코드 구현 / Shadow 전용 / Production 미연결 / 모델 유료 실측 전**

## 왜 이 작업인가

기존 `seyeon-c09-character-first-composer-shadow-v1.ts`의 B/C 경로는 세연의 관심·욕구·결함에 따라 **고정 행동표 없이** 해석과 대사를 생성할 수 있게 만들었으나, `seyeon-fast-dialogue-shadow-v1.ts`는 **검증된 첫 대화 1문항**만 허용한다. 세연이 이전에 어떤 주장을 했고 사용자가 그 말을 어떻게 받아들였는지 연결하는 다중 턴 연구 입력은 존재하지 않았다.

기존의 `seyeon-c09-living-state-shadow-v1.ts`는 특정 문장→욕구/행동을 매핑하므로 새 경로에 연결하지 않는다. 새로운 데이터베이스, 가상 일상 시뮬레이터, 고정된 대사표를 만들지 않는다.

## 이번 구현

- `apps/api/src/seyeon-c09-dialogue-continuity-shadow-v1.ts`
  - 기존 서버 `SeyeonRuntimeContextV2`의 허용된 **최근 대화**만 읽는다.
  - *이전에 세연이 한 말*을 나타내는 message ID를 최대 2개 선택한다. 텍스트를 복사하거나 모델이 '당시 심정'을 추정하여 저장하지 않는다.
  - 현재 사용자 메시지와 최근 대화 ref ID를 함께 넣어, **세연이 전에 말한 입장을 유지·수정·반박할 수 있도록** 후보 프롬프트를 만든다. 어떤 행동이 정답인지는 미리 지정하지 않는다.
  - '세연이 그 말을 했다'와 '세연이 말한 사건이 실제 발생했다'를 엄격하게 구별한다. 영화·장소·만남·관계·장기 취향·사주·과거를 대사만으로 사실화하지 않는다.
  - 기존 `PUBLIC_PERSON_CHARACTER_V1`의 공개 성격을 재사용한다. 동일한 `turn_interpret_render_shadow` 응답 schema, `allowedReferenceVocabulary`, Interpretation/Renderer/Reviewer 계약을 보존한다.
  - 공식 서버의 검증된 CONTEXT라도 **전체 스레드 완료성 검증을 뜻하지 않는다**. 최대 12개의 bounded 최근 대화로만 취급한다.
  - 지금은 관계 없는 PUBLIC 턴, 이전 assistant 발화 존재, 마지막 user 발화, preflight 실행, 무결성 결정 없음, 메모리·공개허가 입력 없음인 경우에만 입력 변환을 허용한다. 변조된 스키마·레퍼런스·다른 모델 목적은 거부한다.
  - 호출 자체는 전혀 수행하지 않는다. 다른 fast Shadow나 Production 라우트의 첫 턴 guard를 느슨하게 변경하지 않는다.
- `test/seyeon-c09-dialogue-continuity-shadow-offline-v1.test.ts`: 동기·입장 연속성 근거, 가상 사건 승격 금지, 참조 봉인 및 부적합 입력 차단을 확인한다.
- 기존 첫 턴 컴포저의 공개 성격 상수를 내보내 새 연구 경로와 같은 정의를 사용한다. 실제 첫 턴 지침이나 출력은 변경하지 않는다.

## 달라지는 점 (개념적인 대화 예)

세연: “저는 웃긴 간판을 찾아보는 쪽이 더 재밌는데요.”
사용자: “왜 하필 간판인데?”

후보 생성 모델은 앞선 **세연의 발화**와 현재 질문을 함께 보고 이유를 밝히거나 생각을 바꿀 수 있다. 그러나 “오늘 실제로 간판 사진을 찍었다”거나 “오래전부터 간판을 수집했다”는 사실까지 확정할 수 없다.

또한 세연: “어제 밤새 영화 봤어요.”라는 기존 대사가 있다고 해도 이는 **그 대사가 있었다는 근거**일 뿐 영화 감상 사건의 공인 기록이 아니다. 세연은 이에 대한 질문을 받을 때 사실 확인 없이 경험을 상세히 이어 붙여서는 안 된다.

## 후속 (기존 로드맵 내)

1. 연구용 multi-turn 후보가 쓰려는 최근 대화의 **서버 소유 전체 스레드 범위·출처 증빙**을 추가한다. 현재 packet은 명시적으로 bounded이며 자체적으로 완료성을 보장하지 않는다.
2. 기존 해석 → 인과/행동 검증 → Renderer 검증 → 독립 Semantic Reviewer의 통합 경로를 오프라인 multi-turn에서 검사한다. 이미 첫 턴만 허용한 `createSeyeonFastDialogueShadowV1`의 eligibility는 바꾸지 않는다.
3. 동일 캐릭터로 3~5턴 연속하여 이전 입장 유지/변경, 억지 맞장구, 사실 없는 회상, 개인적 경계, USER 주장 오염을 검증한다. 독립된 품질 평가는 유료 실행 승인 이후.
4. 관계 발전/기억 저장/캐릭터 현재 삶 기록/운영 모델 변경은 이 작업에 포함하지 않는다.
