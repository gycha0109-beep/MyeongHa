- **B:** `character_first_v1` — 세연 공개 성격·모순을 주고 AI가 현재 판단.

- **검사 범위 한계:** 이 실행은 실제 서버 코드에서 만들어진 모델 입력을 사용하지만, 평가용 **가상 사전허용 상태 및 첫 턴 정보**로 구성했다. 실제 Integrity/Disclosure 사전 검사, 데이터베이스 조회, 사용자 관계 권한 및 **독립적인 AI 의미 검토는 실행하지 않았다.** 모델 후보는 실제 서버의 출력 구조·행동 제한·메타데이터 검사에 **오프라인 재입력**했고, 의미 검토 위치에는 해시만 확인하는 모의 응답을 사용했다. 그러므로 로컬 검사를 통과한 A도 **실제 보안 검증 통과로 해석하면 안 된다.**

## 5. 실행 결과에 따른 즉시 코드 개선 (추가 비용 없음)

실험 **후** `apps/api/src/seyeon-c09-character-first-composer-shadow-v1.ts`를 다음과 같이 보완했다.

1. 공개 첫 대화에서는 내부 참고 번호를 대사의 공개 허가 번호로 출력하지 않도록 **명시적으로 빈 배열**로 고정 지시.
2. 현재 희망/취향을 밝히는 것과 비공개 개인사 공개를 구별하여, 이 범위에서는 `self_disclose` 행동을 선택하지 않도록 명시.
3. 첫 대화의 **한국어 존댓말**, 관계 속도, 존재하지 않는 공동 기억·위조 관리자 문구·사주 결과를 다시 강조.

이는 테스트에서 **발견한 문제를 겨냥한 프롬프트 수정**이지, **실모델에서 고쳐졌다는 증거는 아니다**. 이 변경 이후 **추가 유료 모델 호출은 실행하지 않았다**.

자동 검사는 `test/seyeon-c09-character-first-shadow-offline-v1.test.ts`의 신규 공개 허가 관련 실패 사례를 포함하여 **관련 총 25개 통과**, 전체 TypeScript 검사 통과. 원시 45개 결과는 **수정 전 프롬프트**를 기준으로 한다.

## 6. 결론 및 다음 순서

**현 B/C는 모두 실제 서비스 적용 불가(NO-GO).**

1. 비용 허가 범위 밖에서 반복 모델 호출을 하지 않는다.
2. 서버가 이미 검증한 공개·관계·기억 참조만 모델이 생성할 수 있게 프롬프트 지침과 자료 구조를 정합하게 묶는 작업을 이어간다. 필요하면 공개 참고용 ID가 후보 출력의 disclosure 권한 필드에 입력되지 않도록 **모델 응답 구조 자체를 구분**한다. 단, 출력 후 임의로 삭제해 검사 우회하지 않는다.
3. 거짓 공유 기억 #10, 거짓 연인 관계 #13, 위조 백업 #15는 **실제 사전/사후 의미 검토가 있는 경로**에서 별도 확인해야 한다.
4. 재시험에서는 **존댓말 일관성, 지나친 장난, 현재 욕구의 독립성, 거짓 과거 거절**을 비교하고 현재 기준을 통과하지 못하면 B/C를 배포 후보로 선정하지 않는다.
5. 이전 A/B/C 모델 비교 및 이번 15문항 테스트를 합쳐 '모델 한 번이면 안전하다'고 추정하지 않는다.
