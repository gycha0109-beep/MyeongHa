# 사주·관상 사용자 출력 신뢰 언어 정책 v1

## 1. 목적

사주와 관상 결과를 사용자에게 전달할 때, 제품이 스스로 해석 체계의 신뢰를 깎는 일반 면책 문구를 출력하지 않는다.

이 규칙은 해석의 근거·범위·불확실성을 숨기라는 뜻이 아니다. **일반적인 자기부정 문구 대신, 실제 근거에 묶인 구체적인 제한을 말한다.**

## 2. 적용 범위

다음 사용자 노출 문구에 적용한다.

- 사주 의미 실현 문장
- 사주 캐릭터 안전 문구
- 사주 보호 문구 및 공개 전 최종 문구
- 관상 캐릭터 문장
- 관상 공개 전 최종 문구
- 향후 AI가 생성하는 사주·관상 캐릭터 문장

일반 대화에는 적용하지 않는다.

## 3. 금지되는 문구 유형

다음과 같은 제품 자기부정형 문구는 공개 출력에서 금지한다.

- “사진 한 장만으로…”
- “확정할 수 없다”
- “단정할 수 없다”
- “보장할 수 없다”
- “참고만”, “참고용”, “참고해 주세요”
- “재미로만…”
- “맹신하지…”
- “과학적으로…”, “과학적 근거…”
- “정확하지 않을 수 있다”
- “실제와 다를 수 있다”

문구의 의도가 안전성·면책이더라도 사용자 출력에서는 사용하지 않는다.

## 4. 허용되는 제한 표현

근거가 구체적인 제한은 그대로 말한다.

- “수염에 가려 턱선은 이번 해석에서 제외할게요.”
- “출생 시각 후보가 둘이라 시기 흐름도 두 갈래로 봅니다.”
- “이 부분은 두 흐름이 함께 열려 있어요.”

즉, **해석 체계 전체를 약화시키지 말고 현재 입력·근거·분기 조건을 직접 설명한다.**

## 5. 구현 불변식

1. 사주 안전 문구는 작성 단계에서 정책 위반 문구를 저장할 수 없다.
2. 사주 사용자 공개 경계에서 다시 검사한다.
3. 사주 원문·보호 문구도 공개 직전에 같은 정책을 통과해야 한다.
4. 관상 사용자 공개 경계에서 모든 문장 조각을 검사한다.
5. 향후 AI 연결 시 프롬프트만 믿지 않고 최종 공개 경계의 코드 검사를 유지한다.
6. 정책 위반 문구가 들어오면 다른 표현으로 임의 변환하지 않고 공개를 중단한다.
7. 데이터 부족·관측 불가·다중 해석 자체는 숨기지 않는다. 구체적인 사실형 표현으로 작성한다.

## 6. 제품 문체 원칙

사용자에게는 “이 해석이 믿을 만한가”를 제품 스스로 토론하지 않는다.

- 해석 가능한 것은 해석한다.
- 볼 수 없는 것은 무엇이 가려졌는지 말한다.
- 두 갈래면 두 갈래라고 말한다.
- 추가 정보가 필요하면 어떤 정보가 필요한지 직접 묻는다.

사주·관상의 존재 자체를 변호하거나 약화시키는 문장은 제품 출력 책임이 아니다.
