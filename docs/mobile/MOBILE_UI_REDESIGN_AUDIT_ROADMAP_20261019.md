## 2. 웹에서 재사용할 것과 재사용하지 않을 것

**시각 언어 참고 소스**: `apps/web/product-theme.css`, `apps/web/home-v3.css`, `apps/web/chat-hub.css`, `apps/web/styles.css`.

- 재사용: 종이/아이보리 바탕, 남색 중심 카드, 황동색 선과 강조, 인장색 상태, 동양적 패턴·식물/산수 모티프, 고급 편집물 같은 제목/본문 위계.
- 모바일 전용 재설계: 세로 화면 콘텐츠 밀도, 엄지 터치 영역, 탭 아이콘, 키보드/채팅 입력 영역, 세이프에어리어, 플랫리스트·스크롤, 로딩·접근 제한·빈 상태.
- 비재사용: 웹의 2열 그리드, CSS radial-gradient·pseudo-element·hover 속성을 직접 복사하는 접근, desktop navigation, 웹 특화 공유/리포트 레이아웃.
- 웹 `#0d1b2b` 등과 모바일 `#102A46` 등은 현재 유사하지만 일치하지 않는다. 고정색을 무작정 치환하지 말고 **시맨틱 토큰** 매핑을 먼저 정의한다.

## 3. 시각 방향

**기본 방향: '절제된 고급 사주 서비스 × 캐릭터 중심의 세계관'.**

- 콘텐츠 화면(홈/사주/기록): 따뜻한 한지색 배경, 깊은 남색 주 강조, 황동색 장식은 절제.
- 캐릭터(소개/채팅): 초상화·이름·대화 상대의 존재감 중심. 실제 사용 가능 여부와 기록 권한은 사실 그대로 표현.
- 한 화면에서 위계: 1개의 1차 행동, 1개의 주 카드, 이후 보조 정보. 상태 설명은 사용자가 이해할 문장으로 교체하되 사실을 과장하지 않는다.
- 서체: 가독성 높은 한글 본문을 우선; 자산 라이선스·번들 크기·플랫폼 렌더링을 점검한 후 제목 전용 서체를 검토한다.

## 4. 순차 구현 작업

### MUI-01 — 공통 모바일 디자인 토큰 및 프리미티브

- `mobile-colors`를 즉시 제거하지 않고 기존 API를 보존한 채 semantic color / spacing / typography / radius / elevation / tap target 토큰을 추가한다.
- 공통 `ScreenHeader`, `SectionHeading`, `PrimaryAction`, `SurfaceCard`, `InlineStatus`를 필요 범위부터 구축한다.
- 접근성: 글자 확대, 44~48dp 이상 터치 영역, 스크린리더 이름/상태, 색상에만 의존하지 않는 성공/차단 표시.
- 테스트: 빌드·typecheck·기존 모바일 테스트 무회귀.

### MUI-02 — 홈 첫 화면 고도화

- 상단 첫 화면을 '브랜드/인사 → 우선 정보 → 명확한 다음 행동' 중심으로 정리.
- 기존 `HomeTodayCard`의 사실 출처·loading/birth_required/unavailable/ready 분기를 유지한다.
- 포춘쿠키, 이어지는 이야기, 사주 주제는 콘텐츠 위계를 조정; 상태 없는 추천/허구의 AI 해석 생성 금지.
- 게스트 첫 가치 접근을 로그인 필수로 바꾸지 않는다.

### MUI-03 — 캐릭터 허브 고도화

- 76x90 초상화 행 카드만 나열하는 UI 대신 캐릭터 소개/주력 카드/준비 중 계층으로 정돈.
- 실제 launch roster와 pending roster를 그대로 권한 원천으로 유지한다.
- 'AI 가능' 문구는 실제 접근/HOLD와 모순되지 않도록 검토; 기록 및 답변이 제한 중인 상태를 능력 사용 가능으로 오인시키지 않는다.
- '서버에서 제공하지 않아…' 같은 개발 노출을 적합한 사용자 문구로 교체(기능은 만들지 않음).

### MUI-04 — 채팅 읽기·대화 레이아웃

- 상단 인물 표시, 사용자/캐릭터 말풍선, 상태·보호 안내, 입력 영역, retry·abandon 행동을 시각적으로 분리.
- **`SEYEON_HISTORY_REVEAL_HOLD` / first reveal HOLD / DB authority / 재시도 금지 상태 변경 금지.**
- 전송 가능성, 로그인, 스레드 접근과 기록 공개는 디자인 단계에서도 합치지 않는다.
- 키보드·작은 기기·긴 대화·긴 글자·오프라인 상태를 확인한다.

### MUI-05 — 사주/기록/마이 및 주변 화면

- 해석 핵심 카드 → 근거/상세 보기 → 다음 행동을 구분.
- 검증되지 않은 명식/풀이를 '확정'처럼 렌더링하지 않는다.
- 기록 섹션은 원천/공개 범위/삭제 의미 유지; 오래된 결과와 빈 상태를 구별.
- 로그인 및 출생정보 저장/수정의 실제 계약을 유지한다.

## 5. 명확한 작업 제약

1. 이번 트랙은 **UI 표현·정보 위계**만 다룬다. Supabase prod schema/마이그레이션/데이터/권한/보안 홀드 수정 없음.
2. 화면 이동·상태 분기·토큰 사용 변화는 테스트와 함께 작은 PR 단위로 제출.
3. `docs/UX_SCREEN_STATE_SPEC.md`의 guest first value, 권한, Saju 검증, 기억 공유·삭제, retry/clarification, 접근성 원칙 준수.
4. 세연의 진행 제한을 웹 시안의 '대화 가능'과 동일시하지 않는다. 제품 접근 문구 승인과 기술적 기록 공개 승인은 별개.
5. Android 물리 기기 확인 전까지 스크린샷/실제 렌더링이 완료되었다고 보고하지 않는다.
