# 세연 모델 원가 계측 계약 v1 — 오프라인 후보

Watchtower-Track: character-memory

## 1. 목적 및 현재 효력
- 사용자 턴당 모델 호출 원가를 추정하기 위한 순수 계산 함수. **운영 호출·정산·요금제 활성화 없음**.
- 기존 Responses API 사용량의 `input_tokens`, `output_tokens`, `input_tokens_details.cached_tokens`, `output_tokens_details.reasoning_tokens` 해석을 고정한다.
- 캐시 토큰은 입력 토큰에, 추론 토큰은 출력 토큰에 **이미 포함**된 부분집합으로 취급한다. 중복 청구 계산을 금지한다.
- 가격표는 호출자가 명시적으로 전달하는 서버 소유 버전드 데이터로만 사용한다. 임의의 현재 공급자 가격을 내장하거나 외부 청구 금액과 같다고 주장하지 않는다.
- 비용은 정수 microUSD(미국 달러 100만 분의 1)로 산출하며, 추정 원가를 올림한다.

## 2. 실패 및 보수적 처리
- 사용량 누락 `USAGE_MISSING`, 오염 `USAGE_INVALID`, 단가 미등록 `MODEL_UNPRICED`, 금액 초과 `OVERFLOW`를 각각 분리한다.
- 실패한 호출·타임아웃·재시도 후 사용량이 없을 때 **0원으로 간주하지 않는다**. 예산 예약은 별도 확인 전 보류/차단한다.
- 최대 비용 견적은 입력/출력 토큰 상한을 갖는 모델 호출에만 사용해야 한다. 앱이 입력 상한, 실제 `max_output_tokens`, 회수 제한을 집행하기 전에는 이 함수를 **실제 예산 차단 근거로 사용할 수 없다**.
- 모델별 캐시 단가가 일반 입력 단가보다 큰 이상한 가격표도 보수적으로 더 큰 단가를 견적에 적용한다.
- 모델별 가격표 버전 및 제공자 프로젝트·계정별 실제 청구 차이는 운영 트랙의 별도 검증 대상이다.

## 3. 다음 단계 연계 계약
- AI Provider 호출 **직전**: 서버가 확인한 Subject·Turn·Attempt·Stage 기준의 중복되지 않는 예약 ID를 사용한다.
- DB에서 `remaining >= reserved + ceiling` 조건의 원자적 예산 예약을 수행하고, 열린 DB 트랜잭션 없이 AI 모델을 호출한다.
- 성공: 실제 추정 원가를 기록하며 차액 예약을 해제한다.
- 사용량 누락/타임아웃: 공급자 청구 여부가 불확실하므로 무조건 반환하지 않는다. 상한 보류 후 회수/reconciliation 정책을 적용한다.
- 실패·중복 요청: 사용자 채팅 이용권 차감과 사업자 API 비용 기록을 분리한다.
- 비동기 `event_extraction`/관계 후처리도 별도 예약·계측을 적용한다. 일반 채팅 API 비용으로만 원가를 계산하지 않는다.
- 기존 `ai_execution_logs`의 null 토큰/프롬프트 필드 등을 임의로 수정·보정하지 않는다. DB Authority·Commerce 소유권 계약 승인이 필요한 SQL은 다음 PR에서 다룬다.

## 4. 운영 승격 게이트
A. 정수 단위·캐시/추론 중복 방지·누락·비정상·초과 계산 단위 테스트 PASS.

B. DB 예약·중복·동시성·타임아웃·outbox 재처리 경계를 모의/DB 테스트로 입증할 것.

C. 실제 서비스 호출 라우팅 변경, 요금 차감, 신규 유료 평가 전 반드시 사용자 별도 승인. **현재 PR은 A의 구현이며 B/C는 아님**.
