## 1. 근거 법령과 운영상 제한

적용 지역: 대한민국 국내 소비자 대상 **Web 1회성 디지털 콘텐츠 판매(예정)**.

- 「전자상거래 등에서의 소비자보호에 관한 법률」(2026-07-21 시행) 제17조제1항: 원칙적 청약철회 기간과 서면·실제 공급 시점 관련 기산.
- 같은 법 제17조제2항제5호: *용역 또는 디지털콘텐츠 제공 개시*의 청약철회 제한 및 가분적 미제공 부분 예외.
- 같은 법 제17조제2항 단서 및 제6항: 법정 소비자보호 조치 누락 시 제한을 주장하지 못할 수 있으며, 디지털콘텐츠는 **청약철회 제한 명시적 표시와 시행령이 정한 시험 사용 상품 등 제공**을 함께 요구.
- 같은 법 제17조제3항: 표시·광고/계약 내용과 다른 이행의 법정 청약철회 별도 보장(공급받은 날부터 3개월·알았거나 알 수 있었던 날부터 30일).
- 같은 법 제17조제5항: 계약·공급 및 시점 등에 관한 다툼에서 **사업자의 증명책임**.
- 같은 법 제18조: 유효 청약철회 후 환급·결제업자 취소 요청 의무 등.
- 같은 법 제21조의2(2026-07-21 시행): 정당한 사유 없이 취소·탈퇴·해지 등을 구매보다 복잡하게 하거나 다른 수단으로만 제한하는 등 온라인 인터페이스 방해행위 금지.
- 「전자상거래법 시행령」 제21조의2(2026-07-21 시행): 미리보기/한시적 이용/체험용 디지털콘텐츠, 또는 곤란한 경우 디지털콘텐츠에 관한 정보 제공 중 **하나 이상의 방법**.
- 개별 주문 생산이라는 이유만으로 별도 법정 요건을 건너뛰지 않는다. AI 개인화의 기술적 생성만으로 청약철회 제한을 선언하지 않는다.

## 2. 상품 구성 원칙

**상품 1개 = 특정 공식 Reading을 특정 Reader가 제공하는 지정 범위의 단건 해설 콘텐츠.**

- 구매권: exact canonical Subject × officialReadingId × readerCharacterId × pinned content bundle + immutable Purchase Intent/Receipt lineage.
- 해당 건에서 구매한 해설 본문과 제공 범위가 구체적으로 무엇인지 제품 상세화면·주문서에 표시(형식/분량/요약 포함 여부, 제공 방식·기한, AI 개인화와 한계, 가격/부가비용, 고객 지원/환불).
- **일반 Chat 사용**은 별도 권리. 구매 후 캐릭터와의 일반 Chat 대화 자체를 '유료 해설 제공 개시'라고 취급하지 않는다.
- 후속 유료 질문권·추가 상담·다회 이용권·서로 다른 Reader 해설이 있는 경우, 해당 단위의 가분성·시작 시점과 환불 금액을 별도로 명세한다. 완전히 시작되지 않은 구성요소까지 일괄 '환불 불가' 금지.
- 유료 해설은 Product/Offer/ChargeTerms/Grant/Reader Release/Saju Production/Legal 승인 전 절대 판매 개시하지 않는다.

## 3. 결제 전 필수 표시·확인 — 제품용 문구 후보(법무 검토 전)

### 3.1 상품 상세 화면 / 결제 최종 확인 직전

**상품 예시/정보:** 실제 개인 정보 없이 합성 예시를 제공한다. 예시에는 제공받는 콘텐츠의 구성·범위·완성 형식·AI 생성의 한계·유료 후속 서비스 별도 여부를 분명하게 표시한다. 고객이 결과 전체를 사전에 읽어야 하는 것은 아니다. 실제 결과 예시를 제공하기 곤란하다면 법정 대안인 충분한 콘텐츠 정보 제공 방식의 적합성을 Legal이 사전 심사.

**청약철회 안내(안):**

> 본 상품은 결제 후 제공되는 개인 맞춤형 디지털 사주 해설입니다. 콘텐츠의 제공이 실제로 시작된 이후에는 관련 법령에 따라 단순 변심에 의한 청약철회가 제한될 수 있습니다. 단, 아직 제공되지 않은 가분적 부분과 법령에서 정한 청약철회·환불 사유에는 해당 제한을 적용하지 않습니다. 결제 전 해설 예시 및 제공 범위, 환불 기준을 확인해 주세요.

**별도 확인 문구(안, 기본 해제된 확인 수단):**

> [ ] 상품의 제공 범위, 미리보기/설명, 청약철회 제한 및 법정 예외를 확인했습니다.

- 이 확인은 법적 권리 포기 동의서가 아니다. 본문·상품 정보/시험 제공·계약 내용 전달 요건을 대신하지 않는다.
- 체크하지 않았다는 이유만으로 **법정 청약철회 가능성 자체를 박탈하지 않는다**. 고지·확인 요건이 충족되지 않으면 제한 정책이 아닌 일반 청약철회 처리 대상으로 둔다.
- 구매/취소 선택 버튼은 기만적 색상·위계·반복 확인·숨김 경로로 설계하지 않는다. 지원 연락처·취소/환불 접수 진입을 구매 전후 쉽게 찾을 수 있도록 둔다.
- 최종 문구·고지 방식·기록 보존기간·동의 필요성은 Commerce+Legal 승인 전 상업용 페이지에 표시하지 않는다.

### 3.2 '해설 보기' 화면

> 해설이 제공되면 단순 변심 청약철회가 제한될 수 있습니다. 콘텐츠 구성 및 환불 예외를 확인하신 후 열람해 주세요.

단, 이 버튼을 누른 시점을 실제 제공으로 기계적으로 치환하지 않는다. 서버가 콘텐츠 접근 가능한 상태로 인도했는지에 대한 증거 정의가 먼저다. 자동 체크/숨겨진 선개시/자동 재생으로 제한 요건을 우회하지 않는다.

## 4. 제공 시점 및 증거 — 미구현 필수 사양

| 상태 | 의미 | 단순 변심 제한 판정 |
| --- | --- | --- |
| `PURCHASED_NOT_PROVIDED` | 검증된 결제만 있고 해설 미제공 | 법정 청약철회 기간 내 요청 허용 대상. 선제적 자동 제한 금지 |
| `RENDERING_PRIVATE` | 원격 호출·AI 해설 임시 생성/보호된 출력 | **사용자 제공 개시 증거가 아님** |
| `T2_COMMITTED_UNDELIVERED` | 최종 내부 권한 확인 성공·결과 송신/접근 불명 | **공개 선형화 기술시점과 소비자 법률상 공급시점은 별개**; 자동 제한 불가 |
| `DELIVERED_PROVABLE` | 특정 단건 결과가 해당 고객에게 실제 제공 개시되었다는 검증 가능한 기록 | 사전 고지·시험 제공·기타 법정 조건·예외 확인 후 **단순 변심 제한 검토 후보**. 무조건 거절 아님 |
| `DELIVERY_FAILED` | 오류·타임아웃·미공급·내용 불일치 | 재제공/환불 등 법정 구제 대상으로 판단 |
| `PARTIALLY_PROVIDED` | 여러 독립 구성요소 중 일부만 제공 | 미개시 가분 부분 청약철회·부분환불 검토 |
| `REFUNDED_OR_REVOKED` | Provider/Commerce가 권위를 가진 회수 상태 | 후속 유료 접근 재검증·차단; 이미 소비자가 받은 본문을 되돌릴 수 없음 |

표는 **향후 상태 분류 계약**이지 실제 운영 DB enum/스키마/코드가 아니다. Legal/Commerce가 제공 의미를 정한 뒤 실제 이벤트와 관계를 검토한다.

최소 감사 증거(민감정보 최소화): 확정된 계약/고지 revision, 실제 제공 상품 구성 revision과 가분 항목, 시험 정보 안내 revision, 고객의 별도 확인 결과·시점, 검증된 구매 receipt 연결 키(원문 비저장), 해설 결과 공개 가능한 서버 상태와 실제 인도/접근 사건·시점·구간·결과 식별자, 장애/취소 요청·처리 판정과 reason code. 개인정보·구매 식별자의 retention 기간과 열람권은 별도 승인.

**금지:** 단순 `paid=true`, 프론트 `read=true`, Client timestamp, 서버 내부 생성 시작, 재실행 replay, Receipt verified만으로 `DELIVERED_PROVABLE` 합성. 민감한 사주 생년월일·전문 발화 본문·PG 영수증 원문을 환불 로깅에 복사하지 않음.

## 5. 환불 접수/분류 규칙

1. 접수 단계는 사용자가 직접 접근 가능해야 한다. 사유 선택·추가 증빙을 합리적으로 요청할 수 있으나 단순 변심보다 하자·오결제/미제공 민원을 어렵게 만들지 않는다.
2. **법정 취소/환불 사유 우선 검토:** 계약/표시광고 불일치, 하자, 오결제/중복결제, 결과 미공급/공급 실패, 유효기간 내 미제공분, 통신판매 법정 청약철회, 가분 항목 미개시.
3. 이 예외에 해당하지 않고, 적법한 고지·시험 제공 조치 및 실제 디지털 콘텐츠 제공 개시 증거가 입증되는 단순 변심의 경우에만 청약철회 제한 검토. 법무 기준이 모호하거나 증거 불충분이면 자동 거절 금지, 수동 검토 또는 소비자에게 유리한 처리.
4. 고객 요청 → Commerce 판정/승인 → Provider의 검증된 환불/취소 사실 반영 → entitlement Grant revoke/effectiveAt 갱신. UI가 직접 Grant 또는 paid access를 변경하지 않는다.
5. 환불 접수·승인·Provider 결제취소·Grant 회수·T2 공개 차단은 **각각 다른 사건**이다. 정확한 처리 경계는 #1827의 직렬화/서버 결과 공개 계약에 연결한다.
6. 환급시점·방법·지연배상·증명자료 처리 등은 법정 의무에 따른다. 개인화 AI 생성 비용이 이미 들었다는 사정만으로 법정 환불을 거절하지 않는다.

## 6. 검증 기준(새 테스트/릴리스 게이트)

- `LEGAL-01`: 청약철회 제한 안내가 고지됨 + 시행령 §21-2의 미리보기/한시적 사용/체험/충분한 정보 중 승인 방식 제공. 하나라도 빠지면 '제공 후 무조건 환불 불가' 분기 없음.
- `LEGAL-02`: 구매 미제공/렌더 중/T2 COMMIT만 존재/불완전 인도/Client 위조 read_at → 제공 개시 추정 및 자동 거절 0.
- `LEGAL-03`: 실제 제공 사건·상세 계약 고지 확인·법정 예외 없는 단순 변심만 제한 **후보**로 분류; 예외/증거 불충분은 자동 거절 0.
- `LEGAL-04`: 미제공 가분 후속 상담/추가 Reader 구매는 선행 해설 제공만으로 일괄 제한하지 않음.
- `LEGAL-05`: 이행 불일치/제공 실패/중복결제/법정 취소 요청 경로 확인 및 refund→Grant revoke 반영; 이미 송신된 텍스트 삭제 가능하다는 약속 금지.
- `LEGAL-06`: 결제 전/후 동일 환불 접수 접근성, 모바일·웹 UX 방해행위 회귀, 색상/시각적 유인/강제 체크 회귀.
- `DB-01`: 환불/신규 Grant INSERT/T2 잠금 두 방향 PostgreSQL 경합 PASS; 실생산은 QA·법무 승인 전 OFF.
- `EVIDENCE-01`: 보존할 최소 고지·인도 증빙 정의/개인정보 보존 근거/민감 원문 비노출을 Privacy Owner가 승인.

## 7. 미결정/차단

- Legal: '본 상품'이 정확히 해당 법상의 디지털콘텐츠인지, 가분성, 제공 개시/미리보기 적합성, 계약 고지·확인 방식, 공정위·소비자 분쟁 처리, 영업국가/플랫폼별 약관.
- Product/Commerce: 정확한 saleable SKU, 제공 항목·기간·가격/세금/ChargeTerms, 결과 인도·환불 요청의 서버 이벤트, 별도 후속 유료 상담 SKU.
- DB/Commerce: 실제 환불/취소·분쟁 Provider 프로토콜과 idempotent event ordering, 미래 scope-anchor T2 충돌 안전성.
- UI/Release: 승인된 안내/동의 시안과 E2E 증빙; launch rail Web one-off, Native 구매 스토어 적용은 별도 결정.

**진행 허가:** 정책 문서·내부 상태/테스트 구현은 가능. **금지:** LIVE 환불 자동 거절, 임의 public checkout, paid Reader 응답, Offer 활성화, 법무 미검토 상업적 문구 배포.
