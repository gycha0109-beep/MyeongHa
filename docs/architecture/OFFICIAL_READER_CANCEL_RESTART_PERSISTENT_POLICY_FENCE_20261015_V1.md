# 재시작 이후에도 폐기된 승인 정책을 거부하는 비공개 검증

2026-10-15 · Parent Draft #2091 · OFFLINE SANDBOX / Draft / HOLD

## 목적

기존 프로그램은 실행 도중 최신 보안 정책과 긴급 중단을 확인했지만, 재시작하면 마지막으로 본 가장 높은 정책 번호를 잃어버렸다. 이번 변경은 독립적으로 관리하는 영속 정책 기록이 있다고 가정하고 프로그램을 재시작해도 과거 권한으로 돌아가지 못하도록 하는 검증이다.

## 구현

- 앱 실행에 필요한 최신 서명 정책 번호, 지문, 상태, 루트 및 정책 식별자를 영속 기록 형태로 지정했다. 누락·손상·번호 역행·같은 번호 다른 내용·정책 버전 하향·임의 루트 변경을 거부한다.
- 긴급 중단 또는 서명된 기록의 역행을 발견하면 해당 상태를 영속적으로 중단으로 저장한다. 자동 해제는 금지한다.
- 새 오프라인 실행 경로는 독립 저장소의 원자 비교와 갱신 없이는 시작하거나 실행하지 못한다. 부팅 때, 요청 검증 때, 테스트 DB 저장 호출 직전에 다시 확인한다.
- 이전 오프라인 진입점은 테스트 호환을 위해 남겨두되, 운영 배포에 사용하지 않는다.
- 실제 파일 저장 테스트 모형은 처음에만 신뢰된 초기 상태를 채우고 파일 저장·원자 교체·동기화와 두 인스턴스의 경쟁을 검증한다. 파일이 사라지거나 오염·잠금 오류가 발생하면 사용을 거부한다.
- 테스트는 프로그램 인스턴스를 새로 만들었을 때 오래된 권한 거부, 긴급 중단 유지, 두 인스턴스의 공통 기록, 기록 오염·삭제·동시 잠금, 동일 번호의 다른 서명, 저장소를 외부 요청에서 바꾸려는 시도를 다룬다.

## 반드시 구별해야 하는 한계

1. 로컬 파일은 동일 OS 사용자에게 삭제·복구될 수 있다. 이 파일 어댑터는 테스트용이고 독립된 운영 신뢰 저장소가 아니므로 실서비스에 사용할 수 없다.
2. 실제 운영은 별도 보호된 DB 또는 신뢰 서비스에서 최초 기록 발급, 영속적인 최신 번호, 원자 갱신, 쓰기/삭제 권한 제한, 백업 복구시 역행 차단을 증명해야 한다.
3. 마지막 확인 이후 실제 DB 변경 도중 새 정책이 도착하는 경쟁 조건이 여전히 존재한다. 별도 실행 계정과 DB 거래 내부 최신 정책 검증이 필요하다.
4. 보안 중단 해제, 루트 신뢰 교체, 정책 ID 이관은 별도 승인·감사 기능이 완성되기 전까지 지원하지 않는다.
5. 어떠한 실제 환불, PortOne API 호출, 이용권 회수, 개인정보 삭제, 운영 권한 부여, 배포도 활성화하지 않았다.
