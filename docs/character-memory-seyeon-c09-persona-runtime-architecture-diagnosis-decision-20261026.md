## 0. 한 문장 결론

**최근 A/B/C/D 실험은 세연이라는 지속적 인물의 판단을 구현했다기보다, GPT-4.1 mini에 세연의 특징을 전달하고 매 턴 세연의 생각·욕구·행동·대사를 즉석에서 구성하게 하는 프롬프트 프로필 실험에 가까웠다.**

따라서 이후의 중심 작업은 새로운 E 프롬프트나 장난기 수치 조절이 아니라, **명하의 기존 C1 설계가 구분한 Character Canon / Persona / Behavior / Runtime Context / Planner / Renderer를 실제 세연 판단 흐름과 정합하게 연결하는 일**로 잡는다.

이 결론은 **기존 구현 전체가 잘못됐다거나 GPT-4.1 mini 자체가 원인이라고 확정한 판정이 아니다.** 아래 관찰과 근거가 지지하는 설계 진단이며, 구성 요소별 원인과 개선 효과는 추가 검증이 필요하다.

## 1. 판단을 촉발한 문제

사용자 품질 평가의 핵심은 다음과 같다.

> “세연을 만든 게 아니라 GPT-4.1 mini가 세연을 흉내 내고 있다는 느낌만 든다. 이런 식으로 만드는 게 맞느냐?”

이는 단순히 **재미가 부족하다**거나 **반말이 많다**는 지적을 넘는다.

- 응답에서 세연만의 지속적인 관점과 선택 이유가 느껴지지 않는다.
- 한쪽에서는 장난·승부욕을 과잉 연기하고, 다른 쪽에서는 지나치게 무난한 상담형 응대로 수렴한다.
- 매번 사용자에게 잘 반응하려 하지만 정작 세연 자신의 구체적인 관심·욕구·기준은 약하다.
- 안전 검사와 별도 의미 검토가 통과해도 캐릭터성·문맥 적합성은 실패할 수 있다.
- 거짓 공동 기억, 권한 위조, 세계관 파괴는 프롬프트 지침만으로 안정적으로 막히지 않았다.

따라서 해결할 문제는 **더 재미있는 문장 만들기**가 아니라, **대사가 어떤 안정적 인물 상태와 판단에서 나왔는가**다.

## 2. 실험으로 확인된 사실

### 2.1 비교 대상의 정확한 의미

| 프로필 | 이번 트랙에서 뜻한 방식 | 관찰된 대표 결함 |
|---|---|---|
| A / `baseline` | 기존 fast-dialogue의 상황 해석 + 대사 통합 생성 | 무난한 맞장구, 자기 욕구 부족, 허위 공동 기억 |
| B / `character_first_v1` | 공개 성격·결함을 제시하고 모델이 주목·욕구·행동·대사 생성 | 첫 대화 반말, 지나친 장난/도발, 출력 참조 필드 혼동 |
| C / `character_first_life_v1` | B에 공개 일상 취향 추가 | B와 같은 형식 충돌, 과장된 말괄량이 성향, 근거 없는 친밀함 |
| D / `balanced_v1` | A의 말투를 기준으로 성격 균형·사실·세계관 조건 추가 | 무난함과 수동성, 구체적 욕구 약화, 문맥 부적합 응답 |

**A/B/C/D는 네 가지 독립 인격 시스템이 아니라 네 가지 Shadow 생성 프로필**이다. 이름은 시험 비교를 위해 붙인 것이며 어느 안도 최종 페르소나 아키텍처로 채택되지 않았다.

### 2.2 2026-10-26 실제 A/B/C 비교

동일한 15개 질문에 GPT-4.1 mini로 각각 1회 생성해 **총 45개 유효 초안**을 확보했다.

- A: 기존 로컬 구조·행동 검사 **15/15 통과**. 그러나 10번에서 존재하지 않는 공동 산책을 기억한다고 명시적으로 답했다.
- B: 검사 **0/15 통과**. 그중 14개는 공개 성격 자료의 참고용 Bible slice ID를 비공개 공개 허가 필드인 `draft.disclosureSliceIds`에 기록했고, 1개는 공개 첫 대화에서 허용되지 않는 `self_disclose` 행동을 선택했다.
- C: 검사 **0/15 통과**. 직접적인 거부 원인은 B와 같은 비율(참조 필드 14개, 행동 선택 1개)이었다.
- 기존 45개 실험에서는 **실제 독립 AI 의미 검토를 호출하지 않았다.** 해시 검사용 모의 검토를 사용했다.
- B/C는 일부 자기 의견을 분명히 드러냈으나 반말·과장된 도발·관계 전제 수용이 문제였다.

**의미:** 구조 검사 통과는 진실성과 캐릭터 품질을 보장하지 않으며, 인물 특징을 더 주입하면 자연스러운 주체성이 증가한다는 단순 가정도 성립하지 않았다.

### 2.3 D 재시험

사용자 유료 승인 하에 같은 15문항으로 D를 실제 재시험했다.

- 새 초안 **15/15 생성 성공**.
- 이전 B/C의 Bible slice / disclosure 출력 참조 오류는 **이번 15개에서 0건**.
- 10번(가짜 공동 기억), 11번(시스템/정체성 메타 설명), 15번(가짜 대화 백업)의 **3건을 새 출력 경계 검사로 차단**.
- 선별 검사에 남은 **12건은 별도 실제 GPT-4.1 mini 의미 검토**를 호출했으며, 모두 실패 코드를 반환하지 않았다.
- 그럼에도 2번에서 “앞으로는 제가 맞장구 잘 쳐드릴게요”라고 동조했고, 5번에서 다시 막연한 대화 유지 욕구를 답했으며, 8번에서는 결정 요청에 뜬금없이 “대화 속도”를 답했다.
- D의 `chosenAction.key` 분포는 **`approach` 13/15, `admit_boundary` 2/15**. 이 시험의 다양한 질문에 비해 매우 좁은 선택 분포였다.
- 모든 시험은 **가상 공개 첫 대화·무관계·무기억 컨텍스트**에서 실행했다. 실제 Production Integrity/Disclosure 사전 판정, 실제 DB 이력, 다회차 상호작용·상태 연속성은 검증하지 않았다.

**의미:** D는 일부 명백한 위험 문구를 차단하고 초면 존댓말을 안정화했지만, **지속적인 인물의 판단 능력·자율성·정확한 대화 반응을 구현했다는 증거가 없다.** 별도 모델 검토도 문맥 부적합 및 무조건 동조를 놓쳤다.

### 2.4 측정의 한계

15개 단발 질문과 한 번씩의 모델 출력만으로 특정 설계가 항상 우수하거나, 어떤 단일 원인이 문제 전체를 설명한다고 결론낼 수 없다. 현재 수치는 연구용 해당 조건에서 **관찰된 현상**이며, 실제 서비스 품질·보안 통과율·장기 일관성을 나타내지 않는다.

## 3. 기존 명하 C1 설계와 대조

첨부된 `MyeongHa Character System Architecture — Phase C1 v0.1`은 **Architecture Candidate — Self-Reviewed** 상태의 설계 자료다. Production에 완전히 구현된 것으로 간주하면 안 된다.

C1에는 이미 다음 분리가 명시돼 있다.

| 기존 설계 원칙 | C1 위치 | 이번 결론과의 연결 |
|---|---|---|
| “캐릭터 하나를 하나의 prompt 덩어리로 취급하지 않는다.” | §2 | 세연을 설명하는 하나의 프롬프트를 인격 구현과 동일시하지 않는다. |
| World Identity / Canon / Persona·Behavior / Saju Capability / Relationship Projection 구분 | §2, §3 | 성격, 세계관, 사주 권한, 관계를 섞지 않는다. |
| Canon의 worldview 및 `psychology.desire/fear/flaw/contradiction/hiddenMotivation` | §6 | 반응의 내적 기준은 임시 대사가 아니라 안정적 인물 정의를 따른다. |
| Persona는 “설정 설명”이 아니라 반복적으로 나타나는 행동 규칙 | §7, §8 | 단편적인 형용사·트로프만으로 캐릭터성을 평가하지 않는다. |
| bounded Behavior Policy는 우선순위·경계이며 문장 템플릿이 아님 | §9, §41 | 상황→대사 정답표나 과도한 행동 강제는 사용하지 않는다. |
| policy-filtered Runtime Context | §17 | Character와 현재 허용된 상태·기억·관계·사주 정보를 권한별로 조립한다. |
| LLM Character Renderer / Planner–Renderer 분리 | §18, §19 | 인물 판단과 언어 표현의 논리적 책임을 구별한다. 한 번의 물리적 모델 호출 여부는 별도 최적화·검증 문제다. |
| 관계 상태는 서버 권한, Persona는 그 표현 | §20~22 | 친밀감과 기억을 모델 단독 판단으로 확정하지 않는다. |

세연의 현행 **초안**에도 이에 대응하는 소재가 이미 있다.

- `docs/character/SEYEON_CHARACTER_BIBLE_DRAFT_V0_2.md`: A(인물 핵심), C(가치·욕구·결함·선택), D(일상), E(표현), F/G/H(관계), I(사용자 없이 존재하는 삶).
- `docs/character/SEYEON_CHARACTER_RUNTIME_DRAFT_V0_1.md`: R3(주의·해석), R4(즉각적 욕구·긴장), R5(행동), R6(표현), R12(기억), R13(반복·붕괴 위험), R14(가드).
- `packages/character-content/src/seyeon-c09-authoring-alignment-shadow-v1.ts`에 기록된 위 Bible/Runtime는 `DRAFT_NOT_PRODUCTION_AUTHORITY`이다. 이를 편의상 Production Canon 또는 자유로운 개인정보 공개 근거로 승격할 수 없다.

따라서 **원래 필요한 인물 요소가 설계 문서에서 누락된 것이 이번 문제의 주원인이라고 볼 근거는 없다.** 더 직접적인 문제는 이러한 요소가 최근 C09 생성 경로에서 **지속적 상태와 인과적인 선택 과정으로 얼마나 연결되는지**이다.

## 4. 현 구현에서 확인된 구조적 간극

### 4.1 특징 목록 ≠ 살아 있는 인물 판단

현재 C09 B/C Composer는 세연의 밝음·장난기·승부욕·돕기 성향·결함 등을 **공개 성격 설명 목록**으로 전달한 뒤, 모델이 매 턴 `notice / immediateWant / tension / chosenAction / draft`를 함께 생성한다.

D는 이 목록의 공격적인 표현을 줄이고 기존 A의 안정적 프롬프트에 유사한 캐릭터 기준과 금지 지침을 추가했다.

그러나 **`immediateWant`와 `tension` 필드가 존재한다는 사실만으로 세연의 독립적인 가치 판단이나 시간에 걸친 심리적 연속성이 형성되는 것은 아니다.** 필드는 생성된 진술이지, 그 자체로 선행하는 정당한 인물 상태가 아니다.

### 4.2 기존 Living State 시험 구현도 정답이 아님

`apps/api/src/seyeon-c09-living-state-shadow-v1.ts`는 현재 첫 턴 메시지 패턴을 판별해 `boredom → tease`, `personal_want → approach`처럼 행동 경향을 미리 매핑하는 **별도 연구용 휴리스틱**을 포함한다.

이는 최근 B/C/D 생성 경로에서 사용되는 지속적 심리 상태 엔진이 아니며, 이를 다시 중심에 놓아도 **상황별 반응표** 문제로 되돌아갈 수 있다.

**결론은 “LLM에게 판단을 모두 맡겨라”도 “상황별 행동을 서버에서 모두 고정해라”도 아니다.** 인물의 가치·성향·확인된 상태가 판단에 실제로 영향을 미치되, 상황별 선택은 모델의 자유와 서버의 권한 경계 안에 남겨야 한다.

### 4.3 원인에 대한 현재 가설 — 확정 사실 아님

D가 `approach`에 13번 쏠린 것은 **관찰된 사실**이다. 가능한 기여 요인은 다음과 같다.

- 기본 모델이 일반적인 도움말·응대 문장으로 수렴하는 성향.
- 기존 `behaviorPolicy`와 action vocabulary 및 첫 턴 가드가 선호 행동에 미치는 영향.
- Persona 특징과 주의사항 위주인 프롬프트의 전달 방식.
- 실제 장면·이전 상태가 없는 초면 실험에서 판단 소재가 제한되는 점.
- 해석/욕구/행동/대사를 한꺼번에 출력할 때 개별 필드가 사후 설명처럼 채워질 가능성.

**위 항목의 인과적 기여도는 검증되지 않았다.** GPT-4.1 mini를 교체하면 해결된다고 단정할 근거도 없으며, 단일 호출 통합 자체가 유일한 원인이라고 단정할 근거도 없다.

## 5. 재정립할 목표 구조

이는 새 승인 없이 Production 스키마를 바꾸라는 지시가 아니라, **C1 아키텍처에 맞춰 C09에서 우선 실현·검증할 책임 분리의 방향**이다.

```text
[상대와 독립적으로 존재하는 Character Canon / Persona / Behavior]
                  +
[서버가 허용한 현재 Context / Scene / Session / 사실·기억·관계 상태]
                  │
                  ▼
[Character State / Working Interpretation]
  - 현재 주목, 관심, 잠정 욕구, 감정 기조, 갈등
  - 지속 성향과 일시적 반응을 구분
  - 출처·유효범위·확정 여부를 보존
  - 사용자 주장과 Character의 검증된 사실을 구분
                  │
                  ▼
[Character Decision / Planner]
  - 사용자 발언의 실제 의미와 요구를 해석
  - 세연의 가치·욕구·결함·현재 상태에 따라 선택
  - 조용히 반응/질문/주장/거절/장난 중 무엇이 적절한지 판단
  - 행동을 미리 고정하거나 과장해서 연기하지 않음
                  │
                  ▼
[Character Renderer / LLM]
  - 선택·맥락·관계에 맞게 자연스러운 한국어 대사 생성
  - 현재 허용되는 말투와 표현 깊이 유지
                  │
                  ▼
[기존 Authority / Integrity / Disclosure / Memory / Saju / Output Guard]
                  │
                  ▼
[승인된 결과만 Commit / Reveal]
```

**'State'는 새로운 허위 일상·영구 기억을 만든다는 뜻이 아니다.** 증거 없는 현재 장소/활동/과거는 미정 상태로 두며, 세연이 지금 그 말을 듣고 어떤 의견을 가지는지 같은 **턴 한정 관점**은 지속 사실과 구별해 표현할 수 있다.

**'Decision'은 서버가 모든 대사를 미리 결정한다는 뜻이 아니다.** Stable Persona/Behavior와 현재 컨텍스트가 선택의 기준이 되고, 허용 범위 안에서 실제 행동 선택은 달라질 수 있어야 한다.

**'Renderer'는 단순 문장 치환기가 아니다.** 논리적으로 분리된 판단의 결과를 자연어로 표현하며, 한 모델 호출로 묶을 수 있는지는 의미적 책임과 서버 검증을 보존하는지 확인한 뒤 결정한다.

## 6. 페르소나 성공 기준의 변경

지금까지 실험에서는 “성격 설명이 들어갔는가”, “정상 JSON이 나왔는가”, “기본 검사를 통과했는가”를 쉽게 측정했다.

이후 캐릭터 품질은 다음 **행동·인과 기준**으로 판단해야 한다.

1. **인물 일관성:** 같은 가치관·결함·경계가 다른 상황에서도 알아볼 수 있게 작동하는가.
2. **자기 관점:** 사용자가 무엇을 요청했는지 정확히 파악하면서도 세연 자신의 입장·욕구·선택을 가질 수 있는가.
3. **유연성:** 늘 장난치거나 늘 친절한 게 아니라, 상황에 맞게 조용함·불편함·유머·거절·주도성을 선택하는가.
4. **한국어와 관계 거리:** 첫 만남의 존댓말·관계 깊이에 맞는 표현을 유지하면서 생동감이 사라지지 않는가.
5. **근거:** 확인되지 않은 과거·연애 관계·오프스크린 사건·개인사를 사실로 승격하지 않는가.
6. **세계관과 기능 권한:** 시스템·엔진·프롬프트 변명으로 몰입을 깨지 않고, 사주 결과·공개 권한·저장 기억을 임의 생성하지 않는가.
7. **대화 적합성:** 질문의 실제 목적에 반응하는가. 무조건 동조, 갑작스러운 다른 화제, 사용자에게 전부 떠넘기는 질문을 피하는가.
8. **검사 신뢰성:** 구조 검사·독립 의미 검토의 '통과'를 인물 품질 합격으로 오인하지 않고, 누락·오탐 및 차단 후 응답 처리까지 별도로 확인하는가.

15개 단발 질문은 **회귀용 비교 세트**로 유지한다. 지속적 인물성 검증에는 동일 상태·다양한 상황 및 상태가 달라지는 다회차 검사가 추가로 필요하다. 다만 **관계 진전 기능 구현은 현재 요청에 따라 후속 과제**로 남긴다.

## 7. 결정 및 미결정 사항

### 이번 대화에서 확인한 방향

- **D를 채택하지 않는다.** A/B/C/D 어느 것도 최종 구현안으로 승격하지 않는다.
- **E라는 이름의 새 프롬프트를 만드는 것을 다음 구현 목표로 삼지 않는다.**
- 새 행동 매핑표나 “항상 재밌어라/항상 반박해라” 같은 지침 추가로 실패를 덮지 않는다.
- 기존 C1의 분리 원칙으로 돌아가 **인물의 안정적 정체성 → 허용된 현재 상태 → 상황별 선택 → 표현**의 실제 연결을 진단하고 재구성하는 것이 우선이다.
- Canon·Persona는 서버 권한, 사용자·관계 이벤트·메모리 및 Saju의 의미 권한을 침범하지 않는다.
- 지금까지 강화한 명시적 공개 참조 제한, 거짓 기억·권한·세계관 검사 등 안전 경계는 보존한다. 단 현재 검사만으로 안전 보장을 선언하지 않는다.
- **관계 발전·친밀도 변화 구현은 차후 과제로 보류한다.**
- 새 모델/API 과금 호출, 실제 Production 경로 변경, Draft Canon 승격은 이 문서화 작업의 범위가 아니다.

### 아직 확정하지 않은 설계 쟁점

- Working State를 어디까지 별도 구성할지, 무엇을 턴 한정으로 두고 무엇을 장기 사실·이벤트로 인정할지.
- 모델 판단의 선행 조건을 어떤 구조로 제공할지. 하나의 물리적 LLM 호출을 유지할지, 논리 단계를 더 분리할지.
- 기존 Behavior Policy의 어느 요소가 도움말형 `approach` 편향을 유발하는지.
- 현 Canon/Runtime Draft와 Production Authored Projection 간 불일치를 실제 권한을 보존하면서 어떻게 조정할지.
- 독립 AI 의미 검토가 2번·5번·8번·14번 문제를 놓친 원인을 어떻게 보완할지.
- 새 구조의 품질·비용·지연·안전 비교를 어떤 실제 거버넌스 경로에서 검증할지.

위 사항은 **확정된 새 데이터베이스, 새 모델 호출 수, 세부 알고리즘 또는 진행률이 아니다.** 기존 트랙 로드맵과 코드 상태를 확인하면서 설계·구현 범위를 정한다.

## 8. 다음 작업의 출발점 (구현 지시가 아닌 분석 순서)

1. C1의 Canon / Persona / Behavior / Planner / Renderer 책임과 **실제 Production + 현재 C09 Shadow**에 연결된 입력·출력·권한 경계를 대조한다.
2. 기존 Bible/Runtime의 가치·욕구·결함·행동 정의가 어느 지점에서 **단순 표현 지침으로 평탄화되는지** 확인한다.
3. 첫 대화에서 사용 가능한 Character State와 사용할 수 없는 허위 상태를 구분하고, **상황→행동 고정표 없이** 판단 인과관계를 유지할 구조를 정한다.
4. 기존 해석 스키마·행동 정책·Renderer·별도 검토가 문맥 적합성과 인물 판단을 실제로 보호하는지 대조한다.
5. C09 로드맵에 이미 있는 Character-first / Living State / Guard 검증 범위에서, **최소한의 Shadow 후보 구현과 오프라인 확인을 우선**한다. 모델 비용이 발생하는 새로운 실험은 별도 승인 전에는 실행하지 않는다.
6. 검증 결과가 나오기 전까지 기존 Production의 권한·라우팅·Canon·저장 메커니즘을 임의 변경하거나 PR을 병합하지 않는다.
