# 실제 GEPA 선택 후보의 8축 분리 합성 평가 인계 v2

> 2026-11-13 · character-runtime-lab · 합성 평가 전용 · 유료 API·운영 변경 없음

## 이전 한계와 이번 구현

이전 Python→Node 교차 언어 경로는 GEPA가 선택한 실제 후보에 대해 캐릭터별 점수를 다시 계산했지만, **단일 합성 숫자를 8개 평가 항목에 복제**했다. 따라서 후보의 캐릭터별 총평균이 개선되는 동시에 인격/관계/한국어 품질 중 일부 항목이 악화되는 상황을 표현할 수 없었다.

이번에는 기존 고정 GEPA가 선택한 단일 `shared_expression` 후보를 대상으로, 합성 평가기 안에 **각기 다른 8개 차원 점수**를 정의하고 같은 평가기에서 사용하는 총평균이 그 8개 값의 평균과 일치하는지 확인한다.

1. Python 가상 평가기가 한국어 자연스러움, 응답 관련성, 주도성, 인격 일관성, 관계 적합성, 맥락 유지, 반복, 효율성의 서로 다른 고정 점수를 계산한다. GEPA에는 해당 평균만 반환한다. 실제 원문이나 모델 추론을 사용하지 않는다.
2. 실제 고정 GEPA가 선택한 후보와 시작 후보를 Python의 동일한 가상 평가기로 다시 계산하고, 각 캐릭터의 개발·최적화 검증 가족별 8축 기초/후보 점수를 동결한다. 총평균과 개별축의 일치를 검증한다.
3. Node에서는 **8개 키 정확히 일치·0~1 유한숫자·캐릭터/가족/실행 매니페스트/실제 후보 해시**를 검사하고 기존 비퇴행 집계에 각각의 항목 점수를 넘긴다. 단일 숫자만 전달하거나 가짜 승인/원문이 끼어들면 거부한다.
4. 합성 반례에서 여울은 모든 축이 개선되고, 세연은 전체 평균이 개선되지만 `persona_fidelity` 항목만 하락한다. Node는 세연의 두 가족에서 인격 일관성 퇴행을 보고한다. 전체 평균만 보고 통과시키지 않는다.

## 증명하지 않는 것

- 8개 숫자는 테스트 작성자가 정한 **의도적인 합성 값**이며 실제 한국어/캐릭터 품질·사람의 R16 평가·개선 성능 또는 모델 판단의 타당성을 증명하지 않는다.
- 같은 평가기와 개발/검증 자료를 반복 사용하는 점에서 **독립 평가나 신규 비공개 홀드아웃이 아니다**. 실제 검토 30건, 여울 원본 288건의 별도 출처 인증, 캐릭터별 사람 블라인드 비교는 미완료다.
- 항상 `candidateRegistryStage=proposed`, `ownerReviewGranted=false`, `independentEvaluation=false`, `releaseApproved=false`, `productionEligible=false`, `externalCalls=0`이다.
- 실사용 모델/요금표·USD 상한 및 총 500원 내 비용·송신 승인은 별도 근거가 필요하다. 추가 결제·유료 호출·Canon/기억/관계/사주/DB 변경 없음.

검사 경로: 기존 `.github/workflows/character-gepa-offline-pinned.yml`의 고정 GEPA Python→Node 실행에 새 8축 자료를 연결하고, Node 단위시험에서 위조/누락/비정상값/잘못된 캐릭터를 확인한다.
