# GEPA 가상 평가기 Python 입력·결과 검증 경계 v1

> 2026-11-12 · character-runtime-lab · **연구 전용·합성 입력만·외부 모델 호출 0회**

## 실제로 보정한 실행 경계

기존 Python `gepa_api_contract.py`는 최초 표현 후보의 해시·허용 슬롯을 확인했지만, GEPA가 추가 생성한 후보 문구는 슬롯 이름만 검사했다. 사전 등록되지 않은 개발/검증 평가 예시도 필드 구조만 맞으면 평가기로 전달될 수 있었고, 평가기 결과의 `character_id`는 대상 캐릭터와 대조하지 않았다. 평가 진단 문자열은 자유로운 소문자/밑줄 형태로 허용되었다.

이번 보정은 실제 GEPA `evaluator(candidate, example)` 경계에서 다음을 적용한다.

- **생성 후보:** 단일 표현 슬롯만 허용하고, 공백 문구·1600자 초과·제어 문자·상위 권한/기억/관계 변경 지시를 거부한다. 운영/Canon/세계관/사주를 수정하는 경로는 추가하지 않는다.
- **평가 자료:** 사전등록된 개발 또는 최적화 검증 사례의 ID·캐릭터·가족·분할·콘텐츠 해시가 모두 일치해야 한다. 새로 끼워 넣은 사례, 캐릭터 변경, 봉인 최종평가 자료는 실행하지 않는다.
- **결과:** 점수 범위와 고정된 실패 진단 코드, 캐릭터 정합성, 중복 코드·추가 필드·원문 제외 표시를 확인한다. 유효한 세 필드만 새 객체로 구성해 GEPA에 돌려준다. 테스트용 `synthetic_verbosity`는 인위적 GEPA 검증에서만 쓰이는 진단이며 실제 품질 근거가 아니다.
- **예외:** 평가기 내부 오류 메시지를 그대로 재전달하지 않고 공개 범위가 제한된 오류 코드만 반환한다.

## 재현 및 한계

- 코드: `research/character-optimization-gepa/gepa_api_contract.py`
- 합성 검증: `python -m unittest -v test_gepa_api_contract test_pinned_gepa_offline` (고정 GEPA 소스 CI에서 재현)
- 실제 비공개 원문·사용자 기억·개인 의견을 입력하지 않는다. 이 수정은 의심스러운 메타데이터와 문구가 평가기 경계를 통과하는 일을 줄이는 것으로, **사람 검토/원본 진위/독립 최종평가/실제 품질 개선을 입증하지 않는다.**
- 실제 교사·학생·심사 모델 호출, 진짜 제공자 요금·계정 크레딧·원화 500원 승인 원장, 네트워크 송신은 여전히 미구현/HOLD다. 신규 크레딧 구매·자동충전·실사용 권한 변경은 없다.
