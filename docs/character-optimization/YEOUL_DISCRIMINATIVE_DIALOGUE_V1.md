# 여울 실제 실패 기반 다중턴 개발 평가 초안 v1

> 2026-11-17 · 여울 Character Bible/Runtime DRAFT 근거 · 사용자 검토 전 · 연구 전용

## 이번에 한 일

- 집 PC의 실제 개인 평가 288행을 기존 검증기로 읽고 DeepSeek 72행을 다시 집계했다. good 36/72, awkward 13, flat 9, harsh 5, persona 3, soft 3, fiction 2, other 1. 질문별 양호가 가장 적은 개발 질문은 Y07(0/6), Y03(1/6), Y02(2/6)이다. 사용자 메모나 대사 내용은 GitHub에 게시하지 않았다.
- 기존의 맥락 없는 10개 단문 초안을 최종 평가 자료로 채택하지 않고, 실패 진단용 10개 시나리오 가족 × 3개 사용자 턴 = 30턴을 개인 PC 비공개 폴더에 새로 작성했다.
- 각 가족에는 여울의 실제 DRAFT Bible/Runtime을 근거로 한 별도의 합성 상황, 관계 단계, 예상되는 여울의 행동, 퇴행 징후를 기록했다. 질문 본문에 정답을 직접 지시하지 않는다.
- 평가 범주는 챙김 뒤 감정 축소, 구체적 감정 반응, 책임 경계, 초기 관계의 호감 오해, 근거 없는 질투 방지, 갈등 후 사과, 깊은 관계의 직접성, 기억 진실성, 장난에서 진지한 대화로 전환, 반복 방지로 구성했다.
- 별도 로컬 HTML에서 사용자 3턴과 기대/실패 신호를 확인할 수 있게 했다. PC 원본 288행 및 신규 시나리오를 함께 검증한 결과 10가족/30턴/관계 단계 5종/서로 다른 평가 초점 10종이 확인됐다. Node 단위 검사 4건 통과.
- 비공개 질문·합성 이력·사용자 평점·모델 대사·자유 의견은 저장소 밖에 보관한다. 원본 288건을 수정하지 않는다.

## 평가 방법과 남은 검증

1. 사람 검토: 실제 대화로 자연스러운지, 여울답게 반응할 여지가 있는지, 상황·관계 조건이 모순되지 않는지 판단한다.
2. 실측 비교: 승인된 동일 모델·설정에서 기준 프롬프트와 GEPA 후보가 동일 시나리오·동일 사전 관계 이력을 받도록 실행한다. 사용자 후속 턴은 사전에 고정해 모델별 난도 편차를 줄인다.
3. 블라인드 평가: 사람에게 답변 출처를 숨기고 자연스러움, 여울 고유성, 주도성, 관계 표현, 감정 대응, 일관성, 반복, 사실/권한 위반을 각각 판단한다. 모델이 실제로 다른 결과를 보이는지 확인하기 전에는 변별력 확보를 선언하지 않는다.
4. 자료 분리: 이번 10개는 AI가 만든 개발 진단 초안이므로 GEPA가 참조하는 최종 봉인 홀드아웃으로 승격할 수 없다. 실제 품질 개선 확정에는 별도 독립 평가가 필요하다.
5. 비용·운영: OpenRouter 인증/신뢰 가능한 비용 확인이 막힌 상태에서 실제 모델 호출 0회. 기존 누적 500원 상한 유지. 운영 반영 없음.

이 작업은 기존 로드맵의 여울 파일럿 준비 → 실측 검증을 위한 개발 자료 보강이며, 품질 개선의 증거가 아니다.
