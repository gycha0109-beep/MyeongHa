# Research & Experiment Gate

1. No OpenRouter, teacher, judge, or remote GEPA calls without a separately verified owner budget approval; project work approval alone grants **zero** paid calls.
2. Each run is immutable-source pinned; only one allowed expression slot may change. Canon, character history, memory, relationships, saju, rights and existing content bundle remain unmodified.
3. Historical Yeoul Y01–Y12 / 288 ratings are development evidence, not independent holdout; review candidate counts do not imply acceptance. No user-private text to public CI or external reflection models.
4. With no GEPA installation, the Python runner is only a schema validator and installed-API probe; it cannot optimize prompts. Even after installation, a full file/network sandbox and outbound-only budget gateway must be proven before actual optimizer execution.
5. The Python SQLite ledger is single-host R&D code. It is *not* an authorization source or full security isolation; reservation is mandatory before any future outbound request. Unknown usage keeps its reservation until separately reconciled.
6. GEPA's `max_evals` / `max_token_cost` do not cover total costs, and custom callable spend can show zero inside GEPA. The provider-independent authoritative ledger must cover all roles and final holdout.
7. Sealed holdout must be unreadable by the optimizer at OS level; no `test_set` or optimizer background referencing it. Public scenario files already exposed are not a confidential blind test.
8. Scores, hard failures and user-reviewed quality are separate types of evidence. Promotion is always owner-controlled, tested per character and does not rewrite existing chat content versions.
