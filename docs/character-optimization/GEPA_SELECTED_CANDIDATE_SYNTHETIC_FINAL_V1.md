# 실제 고정 GEPA 후보와 독립 컨테이너의 합성 최종평가 연결 v1

> 2026-11-13 · character-runtime-lab · **실제 유료 호출·실제 개인평가·운영 변경 0회**

## 기존 검증 연결의 공백

기존 CI에는 각각 통과하는 두 흐름이 있었다.

- 공식 고정 GEPA가 생성한 실제 후보를 Python에서 검증·동결해 Node로 넘긴다.
- 별개의 가짜 후보 해시(`bbbb...`)와 별도의 합성 봉인 데이터를 최종평가기 컨테이너에서 단회 집계한다.

둘 다 합성 검사로는 유용하지만 **실제 GEPA가 선택한 후보를 최종평가기와 연결하지 않았다.** 또한 최종평가 전에 데이터가 최적화기로 실수로 전달되는지 일관된 실행 순서로 확인하지 못했다.

## 구현

1. 고정 GEPA가 네트워크가 차단된 컨테이너에서 여울·세연의 공통 표현 후보를 실제 선택한다. 같은 프로세스는 봉인 디렉터리가 마운트되지 않았음을 확인한다.
2. GEPA 프로세스 종료 후 Node의 `gepa-linked-synthetic-final-v1.mjs`가 기존 동결 결과·매니페스트·입력 가족 목록을 다시 검증한다. 고정 공식 GEPA 소스·정해진 합성 학생 모델·고정 자료 해시·기초 문구·두 캐릭터의 개발/검증 네 가족 이외에는 거부한다.
3. 기존 결과에서 **후보 문구나 GEPA 내부 로그 없이** 선택 후보 SHA, 실행 매니페스트 SHA, 여울 개발/검증 가족 식별자와 연구용 차단 필드만 추출해 저장소 밖 별도 0700 디렉터리에 0600 파일로 동결한다. 기존 파일 덮어쓰기 불허.
4. 최적화가 끝난 **후에만** 별도 호스트 디렉터리에 합성 봉인 평가자료를 생성한다. 해당 데이터는 최적화기 입력·Docker 마운트에 포함하지 않는다.
5. 별도 네트워크 차단 최종평가기 Docker에는 합성 봉인자료·해시 전용 동결 후보를 읽기 전용으로, 재실행 기록용 SQLite 상태만 쓰기 가능으로 제공한다. 실제 고정 GEPA 결과에서 추출한 후보 SHA가 최종 평가 결과의 후보 SHA와 정확히 동일한지 확인한다.
6. 합성 최종평가에서 8개 차원 평균과 인격 일관성 하락 사례를 집계하고, 같은 평가자료의 **두 번째 실행은 거부**해야 한다.

## 미확인·금지 사항

- 실제 새 비공개 홀드아웃 확보, 원문 출처 인증, 독립 모델/사람 블라인드 평가, 실제 R16 품질 개선·퇴행 여부는 **아직 전혀 입증하지 않는다**.
- 이 데이터는 CI에 포함된 **공개 합성 데이터**이며 실제 사람의 대화나 과거 H01~H10을 새 봉인 시험으로 승격하지 않는다. 독립 프로세스 격리의 기술적 경계를 점검할 뿐 비공개 시험의 독립성 자체는 아니다.
- 최종평가기의 합성 점수는 GEPA가 실제 선택한 문구를 평가하는 언어 모델의 출력이 아니다. 오직 해당 후보의 식별자를 별도 컨테이너에 전달하는 계약의 작동 증거다.
- 외부 모델 API·추가 크레딧 결제·Canon/사주/기억/관계·실서비스 DB/캐릭터 반영 없음. 사람 검토 30건·가격과 공급자·실측 예산 승인·검증된 실제 홀드아웃이 없으면 유료 파일럿은 계속 HOLD.
- 예산 상한은 **여울 전체 누적 500원**이며 테스트의 `externalCalls=0`은 실제 API 호출 0회라는 의미다.

검증: `.github/workflows/character-gepa-offline-pinned.yml`에 추가된 `Evaluate actual GEPA-selected candidate in a separate one-shot synthetic final container` 단계. 코드·합성 CI 통과 여부와 실제 병합은 별도 확인 후 보고한다.
