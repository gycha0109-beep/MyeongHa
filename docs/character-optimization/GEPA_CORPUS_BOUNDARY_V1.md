# GEPA Node → Python 평가 자료 경계 검사 v1

> 2026-11-12 · 연구용 · 실제 모델 호출/품질 승인/운영 변경 없음

## 구현 이유와 변경

기존 Node의 평가 자료 분할 검사에서는 시나리오 가족의 다른 분할 유입·동일 텍스트의 분할 간 중복을 거부했다. 그러나 Python의 공통 GEPA 입력 경계가 `id`, `familyId`의 자유 텍스트와 중복/분할 충돌을 다시 점검하지 않아, 다른 호출자가 Node 검사를 거치지 않고 직접 파일을 전달하면 위반이 뒤늦게 GEPA 평가에 들어갈 수 있었다.

이번 변경으로 두 경계를 동일하게 묶는다.

- 평가 자료 `id`와 `familyId`: 1~120자 ASCII 식별자만 허용. 원문 한국어 대사, 공백·개행, 경로 분리자, 셸/로그 제어문자 금지. 이는 의미 유사도 검사가 아니다.
- 유효 캐릭터 ID 9개, 개발/최적화 검증 분할만 허용하며, `sealed_holdout`·`long_horizon`은 최적화 실행기로 들어오지 못한다.
- Python은 다시 캐릭터별 `id` 중복, 시나리오 가족의 분할 혼합, SHA256으로 같은 내용이 다른 분할에 나타난 경우를 거부한다.
- Python은 참여하는 **각 캐릭터마다** 개발/최적화 검증 자료가 모두 있는지 확인한다. 공통 트랙의 대상 목록과 비교하는 일은 기존 Node 쪽 실행 명세 검증에서 별도 유지한다.
- GEPA의 `test_set`은 반드시 `null`이고 실제 최종 봉인 자료는 별도 평가기에만 둔다.
- 기존 합성 Python 테스트의 한 건짜리 불완전 자료를 개발+검증 두 건으로 바로잡고, 서로 다른 콘텐츠 해시를 사용한다.

## 검증 경계

- 합성 테스트: Node 식별자 정제, Python 중복/누락·가족 분할·동일 내용 교차 분할·캐릭터별 검증 커버리지·비공개 필드 차단.
- 원본 288개 사용자 평가와 여울 새 합성 가족 8개는 여전히 사람의 의미 중복 심사 및 승인 전 단계다. 새로운 최종 홀드아웃을 생성하거나 실제 모델을 평가하지 않는다.
- 이 규칙은 이름과 해시를 **검증**할 뿐, 신규 자료의 의미상 독립성/품질 개선/사람 검토를 증명하지 않는다.
- 실제 지출 승인, 정확한 교사/심사 모델 선택, 공급자 비용/ZDR의 신뢰 가능한 증명, 사용자 총예산 상한 및 외부 요청 경계는 별도로 보류한다.

실행: `node --test scripts/character-optimization/contracts-v1.test.mjs`, `python -m unittest test_offline test_gepa_api_contract test_pinned_gepa_offline` (마지막 테스트는 고정 GEPA 설치 필요).
