# 실제 고정 GEPA 실행 프로세스의 봉인 파일 마운트 차단 확인 v1

> 2026-11-13 · character-runtime-lab · 공개 합성 자료만 사용 · 유료 모델 호출 0회

## 해결할 실구현 공백

기존 CI에는 별도의 `isolated_runtime_probe.py`를 실행하여 Docker의 `--network none`과 봉인 디렉터리 미마운트를 증명하는 검사가 있었다. 그러나 **실제 GEPA가 최적화되는 Python 프로세스**는 해당 OS 파일 경계 검사를 수행하지 않았다. 최종평가 디렉터리를 실수로 마운트한 상태에서도 GEPA 자체가 실행될 위험이 있었다.

## 실제 수정

1. CI에서 **호스트에만 존재하는** 별도의 합성 봉인 표식 파일을 0700 디렉터리/0600 파일에 생성하고, 실행 전 해당 파일이 실제 존재함을 확인한다. 기존 공개 H01~H10·실사용 사용자 자료는 사용하지 않는다.
2. 고정 GEPA Docker 실행 시 마운트는 읽기 전용 연구 코드와 합성 실행 결과 디렉터리 두 곳만 허용한다. **봉인 호스트 디렉터리는 마운트하지 않는다.**
3. 환경변수에는 호스트 표식의 절대경로만 전달한다. 실제 GEPA 실행 프로세스가 시작 직전에 `optimizer_sealed_boundary_v1.verify_optimizer_sealed_boundary()`를 호출하고, 호스트 표식 경로 또는 정해진 `/private/sealed` 경로의 파일·디렉터리·심볼릭 링크가 컨테이너 내부에 존재하면 실패한다.
4. 모델 비밀키가 프로세스에 있거나 연구 코드 경로가 없는 경우도 실패한다. 테스트는 실제 표식이 보이는 경우, 봉인 마운트가 보이는 경우, 깨진 링크, 상대경로, 비밀키 유입을 각각 거부한다.
5. **부정 경로도 실제 Docker에서 검증한다.** 일부러 봉인 합성 디렉터리를 `/private/sealed`에 마운트한 동일 GEPA 진입점을 실행하면 최적화 시작 전에 `optimizer_can_locate_sealed_source`로 실패해야 한다.
6. 봉인 입력 파일에 접근하지 못하는 정상 구성의 **같은 프로세스**에서 실제 고정 GEPA 오프라인 합성 최적화를 진행한다. 봉인 자료 원문은 입력, 로그, GEPA 반사 자료, GitHub 아티팩트에 추가하지 않는다.

## 경계 및 미입증

- 검증은 컨테이너 내부에서 **특정 호스트 표식 경로와 고정 봉인 경로가 존재하지 않음**을 직접 확인한다. 이는 모든 임의 경로로의 접근, 컨테이너 탈출, 운영 인프라의 전역 접근 권한을 입증하는 보편적 보안 인증이 아니다.
- 호스트 표식은 **인위적인 합성 파일**이다. 실제 새 비공개 홀드아웃이 존재하거나 독립적으로 검토됐다는 증거가 아니다. 기존 공개 H01~H10은 여전히 새 비공개 평가에 사용할 수 없다.
- 이 검사는 호출권한·공급자 단가·USD 원자 예산·30개 사람 평가·실제 한국어 품질이나 캐릭터 비퇴행을 검증하지 않는다.
- 결과 후보는 승인 전 `proposed`에 머무르며 유료 송신·충전·운영 Canon/기억/관계/사주/DB 변경을 하지 않는다. 여울 파일럿 누적 상한 500원 유지.

실행 근거: `.github/workflows/character-gepa-offline-pinned.yml`의 기존 `Prove real pinned GEPA result reaches Node review as unapproved candidate` 단계, `research/character-optimization-gepa/optimizer_sealed_boundary_v1.py`, `test_optimizer_sealed_boundary_v1.py`. 실제 CI의 성공/병합 결과가 확인되기 전에는 격리 성공을 선언하지 않는다.
