# GEPA 독립 최종평가 격리 — 합성 단회 실행 계약 v1

> 2026-11-12 · Character Runtime Lab · 오프라인 합성 테스트만 허용, 유료 모델 호출 0회

## 연결 범위

아키텍처 v0.3의 C 단계(실행기 격리 및 비용/보안 검증)와 D 단계(여울 최종 평가 준비)를 위한 검증 도구다. GEPA 공식 optimize_anything은 test_set 입력 시 별도 최종 시험 평가가 발생할 수 있으므로 이 경로에서 반드시 test_set=None으로 유지하며, 실제 봉인 시험은 GEPA 프로세스와 파일 접근 권한이 다른 실행기에서만 다룬다.

이번에 구현한 research/character-optimization-gepa/sealed_holdout_runner.py는 실제 학생·반사·심사·평가 모델을 호출하지 않는다. 인위적으로 만든 합성 평가행의 검증·집계만 수행하며, 실제 데이터나 새 비공개 홀드아웃, 실측 성능 향상을 입증하지 않는다.

## 실행 격리와 단회 사용

- CI는 최적화 컨테이너를 --network none 및 읽기 전용 코드 마운트로 실행하며, 봉인 입력 디렉터리를 제공하지 않는 기존 접근 거부 검사도 유지한다.
- 최종평가기는 별도의 --network none 컨테이너에서 합성 봉인 데이터·동결된 후보 메타데이터를 각각 읽기 전용 마운트로 받고, 별도의 쓰기 가능한 0700 상태 폴더만 받는다. 코드 마운트는 읽기 전용이다.
- 입력/후보 메타데이터 파일의 0600 권한, 부모 디렉터리의 0700 권한, 입력 경로 구분, 심볼릭 링크 거부, 입력 크기 상한을 확인한다. 모델 자격증명이 있거나 인터넷 직접 접속이 가능하면 실행을 거부한다.
- 입력은 sourceType=synthetic_fixture 외에는 거부하고, 가족 ID가 과거 개발/검증 가족과 중복되면 실패한다. 8개 품질 차원, 하드 실패, 불확실성을 확인하고 2개 이상 가족을 별도 단위로 집계한다.
- SHA-256으로 식별한 합성 봉인 파일은 동일한 **지속성 있는 상태 장부**에서 한 번만 집계할 수 있다. SQLite 고유 키의 원자적 기록은 평가 전에 이뤄지며, 동일 입력으로 다른 후보를 제출하거나 컨테이너를 다시 띄워도 재사용을 거부한다. 상태 DB 파일 삭제·별도 복사/원본 변조 등은 신뢰 가능한 권한 관리 없이는 막을 수 없으므로 이것을 운영 수준의 영구 봉인 권한으로 주장하지 않는다.
- 출력은 가족 수, 평균 품질축 변화, 퇴행 가족 수, 하드 실패 및 불확실성 가족 수와 후보·실행 메타데이터 해시만 포함한다. 가족별 응답·질문·점수나 봉인 원본 해시는 출력하지 않는다.
- 보고서는 **항상** candidateRegistryStage=proposed, independentPrivateHoldoutValidated=false, qualityGainEstablished=false, ownerReviewVerified=false, productionEligible=false, externalCalls=0이다. 합성 테스트의 점수가 좋아도 후보 단계가 올라가지 않는다.

## 확인 및 한계

- 단위 테스트 9개: 최초 합성 평가, 재실행 차단, 다른 후보의 재사용 차단, 개발/검증 가족 침범, 부정한 운영 주장, 개인 텍스트 혼입, 점수·위반 항목 변조, 파일 접근 권한·심볼릭 링크, 점수 하락 집계.
- GitHub CI: 기존 synthetic GEPA 패키지·네트워크 차단 검사를 보존하고, 별도 봉인 평가 컨테이너에서 첫 실행과 **재실행 실패**를 검증한다. 실제 실행 결과는 CI 링크로만 확정한다.
- 기존 여울 288건과 공개 H01~H10은 독립 신규 최종 테스트가 아니다. 실제 비공개 홀드아웃과 진짜 평가 원본의 접근 통제, 사전 등록된 성공/중단 기준, 사람 블라인드 판단, 총 USD 비용 한도 및 승인 권한, 외부 단일 송신 게이트는 모두 미완료다.
- 한 번 사용한 실제 홀드아웃을 재사용하려면 소스 버전과 평가 목적을 별도로 승인받아야 하며, 현재 구현은 **실제 비공개 데이터의 최종 평가 자체를 받아들이지 않는다**. 운영 콘텐츠 버전·권한·기억·관계·Canon·사주 변경 없음.

참고: https://gepa-ai.github.io/gepa/api/optimize_anything/optimize_anything/ (test_set이 최적화 예산 밖에서 평가될 수 있음을 명시).
