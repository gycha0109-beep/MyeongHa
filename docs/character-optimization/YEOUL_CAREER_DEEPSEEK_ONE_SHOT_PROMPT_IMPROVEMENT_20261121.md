# 여울 커리어 DeepSeek 단일 생성 프롬프트 개선 (2026-11-21)

## 결정

- 사용자는 Claude 집필 → DeepSeek 감수 방식 대신 기존 **DeepSeek V4.1 Flash 1017 단일 호출·6장 생성** 방식으로 돌아가기로 결정했다.
- 이번 수정은 기존 단일 생성 경로의 프롬프트만 개선한다. 모델, API 호출 수, 출력 JSON 계약, Saju 입력 데이터, 비용 승인·잠금 절차, 공식 발급 권한은 변경하지 않는다.
- Claude → DeepSeek 실험 결과는 비교 기록으로 보존하며 현재 기본 방향으로 채택하지 않는다.

## 반영 내용

1. **여울 문체 기준 복원**
   - 사용자가 직접 선호한 실제 대화 예시를 시스템 지침에 반영했다.
   - 예시 문장을 해설서에 복사하지 않고 빠른 반응, 툭 쏘는 장난, 승부욕, 행동으로 드러나는 관심의 리듬만 참고하게 했다.
   - 독자와 친분·연애 관계를 가정하지 않으며, 상황에 맞지 않는 장난·걱정·승부욕을 강제하지 않는다.
   - '당신은', '이 명식은', '이 사람은'을 반복하는 제삼자 평가 문체를 줄인다.

2. **6장 역할 분리**
   - 1장: 일하는 기본 방식과 핵심 긴장
   - 2장: 실제 강점과 발휘 조건
   - 3장: 능력이 잘 발휘되는 환경·역할
   - 4장: 강점이 부담으로 바뀌는 지점
   - 5장: 입력된 연도·월 근거의 실제 기간별 흐름
   - 6장: 앞선 발견을 연결한 커리어 판단 기준
   - 각 장의 목적을 사용자 메시지에 구조화해 전달하되, 고정된 문장 템플릿이나 같은 시작·마무리 공식을 강제하지 않는다.

3. **근거 연결 강화**
   - 관련 근거를 단순 나열하지 않고 서로 보강·긴장하는 관계를 설명하도록 했다.
   - 장별 evidenceIds에는 실제 사용한 근거만 포함하도록 명시했다.
   - 근거 ID가 있다는 이유로 근거가 말하지 않는 결론까지 확대하지 않으며, 사실과 종합 해석 사이의 연결 이유를 본문에서 설명하게 했다.
   - 제공된 연도·월 근거를 막연한 주의 문구로 넘기지 않고 기간과 차이를 구체적으로 설명하도록 했다.

4. **과도한 프롬프트 제약 완화**
   - 모든 장을 역설·질문·한 줄 명언으로 시작하거나 끝내도록 강제하지 않는다.
   - 기존의 사실성·시기 경계·개인사 날조 방지·대운 길흉 창작 금지는 유지한다.

## 변경하지 않은 항목

- 모델: `deepseek/deepseek-v4.1-flash-1017`
- 생성 방식: DeepSeek 단일 API 호출
- 장 수·제목·출력 스키마: 기존 6장 JSON
- 사주 입력: Saju 엔진에서 제공한 근거와 제한을 그대로 사용
- 비용 사전 확인, 별도 유료 승인, 단회 잠금, 재시도 금지
- 연구용 입력은 공식 발급·판매로 승격하지 않음
- 기존 GEPA 로드맵, 운영 챗봇 라우팅, Canon·기억·관계·DB 변경 없음
