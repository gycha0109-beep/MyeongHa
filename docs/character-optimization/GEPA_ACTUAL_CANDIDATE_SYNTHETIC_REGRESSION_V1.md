# 실제 GEPA 선택 후보의 캐릭터별 합성 퇴행 검증 v1

> 2026-11-13 · character-runtime-lab · 합성 평가 전용 · 사람 승인·운영 적용·외부 모델 호출 금지

## 기존 문제

기존 고정 GEPA → Python 후보 동결 → Node 접수 검사는 실제 선택된 문구를 전달했지만, 마지막 가족별 평가 집계는 선택된 문구와 무관한 **임의의 0.5/0.5 숫자**를 만들어 검증기에 전달했다. 이 방식으로는 하나의 공통 표현 규칙이 캐릭터 한 명을 퇴행시키더라도 실제 선택 후보와 연결해 검출할 수 없었다.

## 변경된 흐름

1. 오프라인 GEPA가 여울·세연의 공통 표현 슬롯에 대해 실제로 고른 후보를 동결한다. GEPA 실행은 고정 공식 소스·네트워크 차단 컨테이너 안에서만 수행한다.
2. Python은 최적화에 사용한 **동일한 합성 평가기**에 시작 후보와 실제 선택 후보를 각각 평가하도록 다시 요청한다. 캐릭터별 개발·최적화 검증 가족 ID 및 점수만 `synthetic-family-scores.json`에 기록하고 원문·반사 로그는 기록하지 않는다.
3. Node는 동결 후보 SHA, 원래 매니페스트·시작 후보 SHA, 사전등록된 가족 목록과 결과의 각 항목을 대조한다. 대상 캐릭터가 바뀌거나 가족이 누락/중복된 경우, 승인/원문/외부 호출 필드가 끼어든 경우 거부한다.
4. 기존 `inspectCandidateReviewReadiness()`에 **실제 반환 후보에서 다시 평가한** 숫자를 전달한다. 이 가상 평가는 여울이 0.2→0.95, 세연이 0.4→0.3인 시나리오다. 전체 평균이 올라가더라도 세연의 개발·검증 두 가족에서 퇴행이 보고되면 `hasSyntheticRegressions=true`를 확인한다.
5. 출력은 `candidateRegistryStage=proposed`, `ownerReviewGranted=false`, `independentHumanQualityProven=false`, `releaseApproved=false`, `productionEligible=false`, `externalCalls=0`을 유지한다.

## 검증 대상의 엄격한 한계

- 이 검증은 **동일한 합성 평가기와 동일한 가상 가족을 재사용**한다. 독립적인 재평가도, 실제 대사 품질도 아니다.
- 8개 품질 축에 점수를 각각 측정한 것이 아니라 **합성 점수 한 개를 8개 축에 반복 입력**한 연결 검사다. 실제 한국어 자연스러움·기억·행동 선택·비퇴행·통계적 개선을 증명하지 않는다.
- 다른 캐릭터의 실제 독립 평가자료와 여울의 검토 대사 24개·규칙 6개는 여전히 검토되지 않았다. 기존 288건은 개발 근거이고 최종 홀드아웃을 대체하지 않는다.
- 학생/반사/심사/최종 평가 유료 호출이 없고, 총 500원 상한 및 운영 Canon/기억/관계/사주/DB 변경 금지를 유지한다.

CI는 `.github/workflows/character-gepa-offline-pinned.yml`의 기존 단일 흐름 검증에서 Python 동결 결과와 가족별 점수 파일을 실제로 생성하고 Node에서 받는다. 별도 Node 테스트는 결과가 다른 후보/가족에 속하거나 승인·개인 원문이 포함된 경우를 거부한다.
