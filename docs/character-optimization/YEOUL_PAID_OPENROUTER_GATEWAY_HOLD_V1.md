# 여울 OpenRouter 유료 송신 경계 v1 — 기본 차단

> 2026-11-12 · 캐릭터 공통 GEPA 연구 / 여울 500원 파일럿 · **외부 유료 API 송신 0회**

## 이번 구현 범위

`research/character-optimization-gepa/yeoul_paid_openrouter_gateway.py`는 실송신이 가능해질 때 사용할 **단일 OpenRouter HTTP 경로**와 결제 보호 검사 순서를 구현합니다.

1. 고정 DeepSeek 모델, 한 공급자만 허용, 다른 공급자 대체 금지, ZDR, 데이터 수집 거부, 최대 출력 토큰 제한, 대화 입력 구조를 확인합니다. 허용되지 않은 도구·추가 모델·임의 주소·리다이렉트·자동 재시도는 허용하지 않습니다.
2. 신뢰 가능한 사용 승인 출처와 해당 실행에 묶인 확정 요금표·입력 토큰 검사를 요구합니다. **현 시점에 연결된 신뢰 가능한 출처가 없어 반드시 거부**합니다. 이는 500원 한도 승인 자체를 무효화하는 것이 아니라 송신 실행 권한의 출처를 확인할 경로가 아직 없다는 뜻입니다.
3. 위 검사를 통과하는 미래 구현에서는 반드시 한 파일럿의 **엄격한 500원 공동 예산 장부**에 원화/달러 최악 비용을 원자적으로 예약한 **이후에만** `POST https://openrouter.ai/api/v1/chat/completions`으로 송신합니다.
4. 응답의 생성 ID에 대해 `GET https://openrouter.ai/api/v1/generation?id=...`로 토큰·모델·공급자·비용 증거를 조회합니다. 응답 이상·요청 실패·영수증 오류는 동일 시도를 보류하고 후속 전송을 중단합니다. 요청 재시도는 자동으로 하지 않습니다.
5. 공급자 메타데이터가 일치해도 카드 환율·수수료 및 실제 최종 청구가 독립적으로 검증된 것은 아니므로 해당 예약을 `held`로 남깁니다. **메타데이터만으로 자동 정산/추가 호출/운영 변경은 하지 않습니다.**

## 안전한 오프라인 검증

- `test_yeoul_paid_openrouter_gateway.py`: 실제 네트워크 없는 모의 HTTP/모의 생성 메타데이터만 사용.
- 검증 사항: 승인/위조 주장 거절, 엄격한 원화 장부 의무화, 고정 주소·단일 공급자·토큰 상한, 인증키 누락 시 예약 불가, 응답 비용/모델 불일치 거절, 전송 중단 후 다른 실행 차단, 성공한 모의 응답도 청구 불명으로 보류.
- 로컬 `python -m unittest -q test_yeoul_paid_openrouter_gateway test_krw500_synthetic_ledger`: **27건 통과**. 새 모듈도 기존 오프라인 GEPA 워크플로에 별도 등록했습니다.

## 실송신의 남은 필수조건

- 실제 OpenRouter 계정의 유효한 추론키와 기존 크레딧 검증(신규 구매·자동 충전 불허)
- 신뢰 가능한 사용자 승인 출처를 실행 승인 원장과 연결하고 현재 500원 누적 상한에 결박
- 공급자별 확정 단가, 입력·출력·추론 및 기타 청구 항목 상한, 환율/수수료 상한을 인증하고 원장 정책에 적용
- 입력 토큰의 검증 가능한 상한(문자 수를 토큰 수라고 가정할 수 없음)
- 공급자 청구와 결제 금액의 독립 대조, 보류 해소 절차, 단일 운영 송신 게이트와 네트워크 우회 차단

현재 실사용 결제 권한을 생성하지 않았고, 사용자 한도를 추가 승인으로 오인하지 않습니다. **이 문서는 유료 송신을 활성화하는 절차가 아닙니다.**
