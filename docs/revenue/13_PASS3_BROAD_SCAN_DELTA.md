# 2. H-R07 Premium Compute — strengthened, but role corrected

**Previous status:** LEADING / revenue component  
**Pass 3 status:** **STRONG COST-RECOVERY / MARGIN-PROTECTION LAYER**

Kindroid directly states that very high-context tiers exist because serving them is expensive and may be break-even or loss-making even at much higher prices.

### Delta

Do not forecast Premium Compute as a major profit center by default.

More defensible role:

```text
prevent heavy-user cross-subsidy
recover high-context cost
protect standard subscription margin
offer high-cost experience without degrading free/core tier
```

It may still produce margin if routing becomes efficient, but that must be measured.

# 3. H-R10 Compatibility / Gift — strengthened

**Previous status:** HIGH growth candidate  
**Pass 3 status:** **HIGH, strengthened by adjacent membership/gifting evidence**

Patreon and Finch both normalize gifting/subsidized premium access.

MyeongHa candidate products:

```text
compatibility gift
one Reading gift
fixed-term membership gift
premium artifact gift
```

The strongest version is not a generic coupon.

It is:

```text
payer buys meaningful object
→ recipient has reason to create own identity/Birth Record
→ recipient activates
→ new account / potential payer
```

This remains one of the most attractive revenue + CAC-reduction combinations.

# 4. H-R12 Authored Episodes / IP — upgraded from distant idea to explicit option value

**Previous:** medium/later  
**Pass 3:** **OPTION VALUE PRESERVE / DO NOT BUILD EARLY**

Love and Deepspace demonstrates that emotional/character IP can monetize far beyond dialogue via:

- recurring pass;
- limited content;
- visual memories;
- collectible/event content;
- outfits and other content objects.

MyeongHa should preserve architecture that allows later:

```text
premium authored episode
voice pack
visual memory
seasonal world content
cosmetic collection
```

But only after:

```text
character return-rate proof
character preference concentration
episode completion demand
willingness-to-pay for IP independent of Saju
```

No early gacha recommendation.

# 5. H-R15 Human Expert Marketplace — upgraded as strategic later-stage path

**Previous:** OPTION VALUE / LATE  
**Pass 3:** **STRONGER OPTION VALUE, still LATE**

AstroTalk's scale shows paid human astrology consultations can support a very large business.

But the marketplace operational stack is large enough that early adoption would distort MyeongHa into a different company.

Activation gate before building:

```text
material users explicitly ask for human escalation
AND
AI/deterministic product already has meaningful paid demand
AND
expected expert AOV/take-rate covers operations/QA/support
```

Until then, preserve only integration boundaries.

# 6. New H-R18 — Layered Value Monetization

**Status: NEW META-HYPOTHESIS / PASS 3**

H-R18 does not replace H-R17.

H-R17 answers:

> access boundary.

H-R18 answers:

> monetizable value taxonomy.

Proposed taxonomy:

```text
L0 RELATIONSHIP
ordinary continuity / chat

L1 INQUIRY
one new bounded grounded question

L2 ANALYSIS
multi-axis / timing / comparison

L3 ARTIFACT
saved structured report / compatibility / annual dossier

L4 EXPERIENCE
multi-character / voice / visual / authored episode

L5 HUMAN / SOCIAL
expert session / gift / couple product
```

The hypothesis:

> Users will show different willingness-to-pay at each layer, and forcing all layers into one subscription or one currency will leave money on the table or damage immersion.

---

# 7. H-R18 implementation implication

Architecture should permit separate pricing without requiring separate runtime semantics.

For example:

```text
L1 Analysis Right
→ one new governed semantic execution

L2 Decision Analysis
→ multiple bounded sub-executions + structured comparison

L3 Artifact
→ immutable/saved/exportable packaged value

L4 Premium Experience
→ same grounded semantics + more expensive rendering/modality
```

Saju semantic authority remains independent of payment.

Payment changes:

- scope;
- depth;
- packaging;
- compute;
- modality;
- convenience.

Not truth validity.

# 8. Membership interpretation changes again

Pass 1 risk:

```text
membership = pay to chat / remember more
```

Pass 2:

```text
membership = more allowance + continuity + premium value
```

Pass 3 refinement:

> Membership should bundle **recurring benefits across multiple value primitives**, not exist solely to hide a quota.

Candidate bundle later:

```text
X grounded inquiries / month
+ one structured artifact credit or discount
+ deeper continuity tools
+ premium compute allowance
+ content/IP benefit when available
+ ad-free if ads ever exist
```

This gives membership a reason to exist even if basic relationship access stays open.

Exact X, price and included value remain unknown.

---

# 9. Subscription-led control remains required

Nothing in the broad scan justifies removing S1.

Calm, Finch, CHAI, Tinder, Jamo and many adjacent apps all prove recurring subscription can be a major monetization primitive.

But they monetize different things.

Therefore the future experiment should compare not merely:

```text
subscription vs no subscription
```

but:

```text
what the subscription bundles
```

### S1A

Subscription primarily gates sustained grounded-analysis access.

### S1B

Open relationship + subscription bundles allowance/continuity/premium benefits.

This distinction may matter more than the exact monthly price.

---

# 10. New caution — lifetime plans

Calm and other content libraries can sell lifetime access because marginal content-delivery cost is relatively bounded.

MyeongHa has open-ended inference cost.

Therefore:

```text
Lifetime unlimited AI
→ NOT recommended
```

A lifetime product is only rational if it means something bounded, such as:

- lifetime access to purchased static artifacts;
- one-time permanent feature unlock;
- content archive entitlement;

not unlimited future LLM usage.

---

# 11. New caution — emotional premium-choice design

Interactive fiction and romance live-service show high monetization potential but also a severe trust failure mode.

MyeongHa should explicitly avoid:

```text
pay to receive the kinder response
pay to avoid character rejection
pay to stop relationship decay
pay to unlock affection confession
```

If premium episodes later exist:

```text
pay for episode
!=
pay for dignity/affection inside episode
```

This strengthens No Pay-to-love from a moral principle into a product-economics principle: coercive emotional monetization can damage long-term trust and retention.

---

# 12. New caution — monetization should not contaminate Saju recommendations

AstroTalk's later e-commerce expansion proves commerce adjacency can be large.

But MyeongHa's deterministic authority makes this especially sensitive.

Potential conflict:

```text
Reading says X is favorable
→ platform happens to sell X-related product
```

This creates incentive contamination.

Therefore physical/product recommendation commerce is **LOW PRIORITY** and requires a separate conflict-of-interest policy before any future test.

# 16. What would falsify the layered model?

H-R18 loses value if real telemetry shows users overwhelmingly want only one simple purchase model.

Examples:

```text
subscription converts strongly
AND users rarely buy standalone artifacts
AND allowance UX adds friction
→ simplify toward subscription-led
```

or:

```text
standalone Reading purchases dominate
AND relationship retention lift is weak
AND membership attach is poor
→ simplify toward transaction-led fortune commerce
```

or:

```text
relationship/IP spending becomes material
while Saju transactions flatten
→ product may evolve toward character live-service
```

The architecture should enable simplification after evidence.

# 17. Next research priority after Pass 3

Broad-market ideation now has diminishing returns.

The next valuable questions become narrower and quantitative:

1. actual MyeongHa `C_chat / C_read / C_artifact / C_premium` estimates;
2. real WTP for Korean structured Saju products;
3. how many distinct grounded questions users naturally ask per active month;
4. whether users value continuity/memory enough to subscribe;
5. whether gift/compatibility creates activated second users;
6. whether relationship cohort retention materially exceeds static-report cohort.

Until then, adding more BM patterns is less useful than measuring these unknowns.
