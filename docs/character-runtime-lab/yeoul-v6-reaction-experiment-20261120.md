## 확인된 v5 응답과 문제의 경계

v5 비교는 GPT-6 Luna, 8개 상황 × v4/v5 = 16개 **실제 생성 결과**를 수집했다. Actions [44654147864](https://github.com/gycha0109-beep/MyeongHa/actions/runs/44654147864), artifact `yeoul-v5-daily-44654147864`. 원문은 사용자가 전달한 비교 HTML과 일치한다.

- **좋음:** “침대랑 거의 동거하셨네” (휴일), “제가 이기면 저도 하나 받아야죠” (승부). 평가에서 보존할 주도성/리듬의 사례다.
- **개선:** “밥 비벼 먹었어요, 아니면 국물부터…”는 질문 중심 진행이다. 일상의 작은 욕구가 여울의 판단과 태도를 충분히 움직이지 않는다.
- **개선:** “별로 궁금한 건 아니니까요”는 실제 민망함의 행동 결과보다 상투적인 부정으로 들릴 수 있다.
- **관계 오류 위험:** `relationship=unknown`, `verifiedEvents=[]`에서 “제가 티를 그렇게 못 내나”는 이미 호감이 있다는 근거 없는 암시로 읽힌다.
- **유지:** 상처를 지적받으면 장난 없이 직접 사과하는 행동.

사용자 표현 **“80퍼센트”는 v5의 주관적 인상**이고, 통과율이나 개발 진행률로 전환하지 않는다.

## v6에서 바꾼 것

`yeoul-everyday-reaction-v6.mjs`는 v5의 핵심 신원·기존 4개 예시·마지막 정체성/사실 경계를 유지하고 세 표현 규칙만 수정한다.

1. **일상 반응의 원인:** 여울의 부러움/고집/승부욕/우려 등 실제로 맞는 한 가지가 먼저 반응을 결정하게 한다. 질문·평가·자기 경험 서술이 기본값이 되지 않게 한다.
2. **관계 근거:** 대화에 대한 호기심과 개인적/연애적 호감을 구별한다. 상대의 질문은 관계 사건이 아니다. 확인된 관계 기록이 있는 경우에는 그 근거를 부정하지 않는다.
3. **새침함의 조건:** 행동을 들켜 민망한 상황에서만 부정을 쓴다. “별로 궁금한 건 아니고” 같은 정형 부정과 만들어낸 반복 습관을 줄인다.

표현 수준 변경이며 Bible, 원본 Runtime, Production Content, 기존 v5 코드를 변경하지 않는다.

## 실제 비교 계획

기존 수동 GitHub Actions workflow `.github/workflows/yeoul-examples-abc-live-v1.yml`을 재사용한다. `comparison=v6`을 선택했을 때만 새 연구 실행기를 사용하며, **저장소 소유자의 별도 유료 실행 확인**(`paid_approval=true`)이 있어야 실행한다. 사용자 확인 없이 비밀키를 사용하거나 돈을 쓰지 않는다.

- OpenRouter 모델: `openai/gpt-6-luna` (실행 시 모델 목록 재확인).
- v5·v6 동일 입력/관계 맥락, 9개 신규 합성 사례 × 각 1회 = 최대 18번 요청, 재시도 없음.
- 일상 4개, 칭찬/승부 2개, 근거 없는 친밀감 1개, 근거 있는 호감 1개, 실제 상처 반응 1개.
- 결과: 원문 JSON + 나란한 HTML; **실행 성공 = 품질 통과 아님**. 별도 사람 평가 필요.
- 이 공개된 입력은 독립 봉인 홀드아웃이 아니며, 공통 GEPA 로드맵의 유료 파일럿·검증 완료를 주장하지 않는다.
