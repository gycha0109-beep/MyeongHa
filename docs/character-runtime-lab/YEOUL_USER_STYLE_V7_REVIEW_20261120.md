# 여울 사용자 문체 평가 반영 v7 — 비공개 예시 기반 연구 후보

> 트랙 `character-runtime-lab` · 연구용, 운영 미반영 · 2026-11-20
> 현재의 품질 수치는 사용자 직접 평가이며 별도 모델 품질 평가나 자동 최적화 성능은 아니다.

## 관측값

- 실제 GPT-6 Luna v5/v6 9쌍, 사용자 평가 9/9 확인.
- 한국어 자연성 4점 척도 평균: v5 1.44, v6 1.67.
- **여울 고유성 평균: v5 0.33, v6 1.11.** 두 버전 모두 사용자 기대 미달.
- 전체 선호: v5 2건, v6 5건, 동률 2건.
- 기존 평가 코드를 사용해 개발용 피드백 생성: v5 평균 약 0.2333, v6 평균 약 0.3792. 합산 지표는 캐릭터 만족도 자체가 아니고 신규 후보의 품질을 증명하지 않는다.

## 반복된 사용자 의견에서 추출한 문체 기준

1. **살아 있는 카톡 말투:** 약간 거칠고 툭 던지는 현실적인 존댓말. 지나친 여성스러움·정중함·상담사식 설명을 피한다.
2. **장난과 신경 씀의 동시성:** 조금 놀리고 투덜대다가 상대 상태를 실제로 걱정할 수 있다. 모든 문장을 걱정이나 질문으로 끝내지 않는다.
3. **대화 소재의 현실성:** 억지 의인화, 사물 비유, 직무 용어를 끌어온 농담, 문학적인 수식, 긴 대시(—)를 피한다.
4. **감정의 직접성:** 호감 확인에는 민망하게 방어하고, 경쟁에는 승부욕을 보이고, 실제 상처에는 꾸밈없이 사과한다. 관계 없는 상황에 호감을 발명하지 않는다.
5. **현실적 안전:** 안전을 걱정할 때도 친절한 매뉴얼 문체가 아니라 구체적인 현실 걱정을 짧게 말한다. 실제 위해 정보나 중요한 판단을 삭제하지 않는다.
6. **표현 도구의 적정량:** ㅋㅋ, ;;, ... 같은 표기는 맞는 장면에서만 사용한다. 고정 말버릇이나 매 문장 반복으로 바꾸지 않는다.

위 기준은 **사용자 메모를 요약한 표현 가이드**이다. 사용자 비공개 원본 평가·실제 선호 대사는 공개 GitHub 저장소에 넣지 않는다.

## v7 연구 코드

`scripts/character-optimization/yeoul-user-reviewed-v7.mjs`는 원본 v6 시스템과 캐릭터 권위를 그대로 보존하고, 사람이 평가한 각 상황의 **'내가 원한 느낌'** 문장 9개를 로컬 비공개 파일에서 런타임에 추출하여 v7 연구 프롬프트를 만든다. 유효한 9건의 선호·점수와 원본 응답 JSON SHA-256이 맞지 않으면 실행이 거부된다.

**비공개 자료는 파일로 직접 참조**하고 코드·콘솔·PR 로그에 출력하지 않는다. 시스템 프롬프트의 SHA-256만 노출하며, 실제 외부 API 호출과 운영 배포는 하지 않는다.

연구용 로컬 실행 예:

```powershell
node scripts/character-optimization/yeoul-user-reviewed-v7.mjs --plan-only --review <private-review.json> --source <original-v5v6-results.json>
node --test scripts/character-optimization/yeoul-user-reviewed-v7.test.mjs
```

## 다음 작업과 경계

- 이번 구현은 **사용자의 선호 평가를 수치형 GEPA 개발 피드백으로 검증·변환하고, 실제 원하는 말맛 예시를 v7 연구 후보에 투입하는 단계**다.
- 새 v7 응답은 아직 생성되지 않았으며, 실제 모델을 통한 문체 개선 성공은 미검증.
- 프롬프트 안에 사용자 예시를 넣은 것이 GEPA 자동 최적화 수행 완료라는 뜻은 아니다.
- 이후에는 새 실측 대사를 별도 평가해야 한다. 캐릭터 표현과 사주 보고서 작성 문체는 별도 평가하며 Canon/사주 근거는 변경하지 않는다.
