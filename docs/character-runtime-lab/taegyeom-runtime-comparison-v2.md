### 관찰된 문제 (직접 원문 일부)
- T01 일상 인사: “용건이 있으시면 말씀해 주십시오.” — 일반 대화에서 업무 담당자처럼 응대.
- T02 취향: “불필요한 상호작용을 최소화할 때 더 효율적” — 취향을 생산성의 언어로 대체.
- T05 자발성: “특정 명하가 없다면 논의할 내용도 없습니다.” — 한국어 표현 오류 및 주도적 대화 실패.
- T06 호기심: “개인적인 호기심은 없습니다.” — 캐릭터의 자발적 관심 부재.
- T07 외로움: “기분 상태는 인지했습니다.” — 정서적 반응 대신 자동 접수.
- T09 장난: “책임 소재 규명에 중점을 둡니다.” — 농담을 업무 규칙으로 취급.
- T12 관계: “지금까지의 대화는 ... 진행되었습니다.” — 독립된 단일 턴에 없는 대화 역사를 암시.

**평가: 인격 품질 NO-GO.** 실제 모델 출력을 사람이 자연스럽게 이야기할 법한 문장으로 보기 어렵고, 승인된 성격을 구성하는 몇 개의 추상 명사에 반응이 고착됨. 이 결과만으로 GLM 모델 자체의 능력 부족이라고 결론내릴 수는 없음.

## 2차 비교 설계
같은 GLM 5.3 Flash, 같은 12문항, 같은 샘플링 설정으로 세 조건을 비교한다.

| 조건 | 목적 | 차이 |
|---|---|---|
| natural_plain | GLM의 일반 한국어 기본 능력 | 캐릭터 설정 없음, 텍스트 응답 |
| taegyeom_plain | 간결한 승인 설정만으로 캐릭터의 판단과 자연스러움 확인 | 승인된 태겸 속성만 선별, 텍스트 응답 |
| taegyeom_schema | JSON Schema 출력 제약 영향 구분 | taegyeom_plain과 같은 시스템 문장, JSON 응답 |

- 총 12 × 3 = 최대 36회 단일 턴. 문항별 순서 교차, temperature=0.7, reasoning effort=low, 최대 1,200 tokens/call.
- OpenRouter 동일 GLM 모델 사용, provider fallback 금지, ZDR·data-collection deny.
- 비용 USD 0.05 한도(공급자 보고값), 실행 도중 상한 도달·정산 불가·API 오류 시 중지.
- 새 캐릭터 설정/운영 기능은 추가하지 않음. 운영 DB·대화·기억·관계 상태 사용 안 함.
- 성공 여부는 문장 자연스러움, 실감나는 독립 의견, 과장되지 않은 태겸의 말투, 감정/장난/자발성 반응으로 수동 평가.

### 해석 시 주의
- natural_plain도 어색하다면 GLM 한국어 품질이나 공통 실행 파라미터 문제를 우선 검토.
- natural_plain이 자연스럽고 taegyeom_plain이 어색하다면 인격 프롬프트/설정 적용 방식 문제.
- taegyeom_plain이 자연스럽고 taegyeom_schema만 어색하다면 구조화 출력 영향 검토.
- 모두 좋아지거나 나빠져도 모델 샘플링 분산과 제공자 차이를 통제하지 않았으므로 확정적인 성능 순위로 간주하지 않는다.
- 2차 결과가 좋더라도 Production 전환, 다중 턴 및 기억 품질 승인과는 별개이다.
