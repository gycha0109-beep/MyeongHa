# 명하 공통 메모리 — 사용자 승인 결정 v1

> Watchtower-Track: character-memory
> Owner-approved: 2026-11-09
> Scope: 마이페이지의 공통 메모리 한 공간. 사용자 수동 등록·수정·삭제. 모든 캐릭터에게 동일한 소유자 메모리 조회 자격 부여.

## 승인된 사용자 동작

- 마이페이지에서 직접 작성한 짧은 메모 여러 개를 한 **공통 메모리 공간**에 보관한다.
- 모든 캐릭터는 **동일 회원 Subject의 해당 공통 메모리**를 조회할 수 있다. 캐릭터별 복사본과 각 메모의 승인 팝업은 만들지 않는다.
- 캐릭터의 현재 턴에 관련 있는 항목만 선택해 정확히 계수한 모델 요청에 전달한다. 전부를 무조건 주입하거나 언급하지 않는다.
- 수정/삭제는 사용자가 직접 수행한다. 삭제한 원문은 공통 메모리 표에서 실제 DELETE하고 다음 요청부터 조회하지 않는다.
- 캐릭터의 대화 자동 채집·장기 저장은 **비활성**. 향후 AI가 메모리를 제안하는 기능은 별도 과제로만 보유하며 지금은 구현하지 않는다.
- 공통 메모리는 **사용자가 진술한 정보**이지 검증된 외부 사실이나 캐릭터의 개인 지식이 아니다. 사주 공식 해석·캐릭터 비공개 설정·관계 이벤트로 승격하지 않는다.

## 구현 경계

- 새 공통 메모리는 기존 DB 안의 독립된 member-owned 수동 저장 레인이다. 기존 'memory_items'·'memory_proposals'를 우회해 임의의 자동 승인 기록을 만들지 않는다.
- 기존 SRC-05(자동 후보 임시보관), SRC-25(기존 장기기억 유형/값 등록부), SRC-10(캐릭터별 grant 생성)는 **미해결 유지**. 이번 사용자의 공통 메모리 결정이 이들 전체를 종결시키지 않는다.
- RLS 및 사용자 확인이 있는 API 실행 역할만 원문을 읽고 고친다. Guest 및 비활성/삭제 대기 회원은 거부. 1개 메모 최대 500자, 회원당 50개는 v1 구현상 한도이다.
- 응답·로그·진단 이벤트에는 원문을 기재하지 않는다. 클라이언트 화면과 같은 Subject의 서버 컨텍스트에만 노출한다.
- 새 운영 데이터베이스 마이그레이션 적용 및 운영 엔드포인트 활성화는 **별도 검증 후**. 기본 배포 플래그 MYEONGHA_SHARED_MEMORY_ENABLED=0으로 차단한다. 기존 모델 호출/요금/캐릭터 게시도 이 결정만으로 켜지지 않는다.
- 사용자 계정 삭제/복구·백업 보관에 관한 기존 운영 삭제 규칙을 변경하지 않는다. 공통 테이블은 Subject 물리 삭제 시 CASCADE하며, 활성화 전에 계정 삭제 동작과 현재 백업 정책의 독립 확인이 필요하다.

## 2026-11-10 — 사용자 승인: 개별 메모리 삭제 후 백업 복구

- 회원이 직접 삭제한 공통 메모리의 **원문을 즉시 실제 DELETE**하고, 같은 PostgreSQL 거래에서 최소 삭제 이력을 기록한다. 복구 이력 기록 실패 시 원문 삭제도 롤백한다.
- 이력의 개인정보 항목은 **메모리 UUID, 소유자 Subject UUID, 삭제 시점**으로 제한한다. 원문·요약·캐릭터별 복사본·관계 기록은 만들지 않는다.
- 기존 읽기 전용 `AUTHORITATIVE_CAPTURED_WINDOW_V1` 추출 및 암호화된 별도 Privacy Ledger, **P30D** 보관을 그대로 활용한다. `MEMORY_ITEM_REVOKED` 대신 수동 노트 전용 `SHARED_MEMORY_NOTE_DELETED` 유형을 사용한다.
- 과거 백업 복원 시 정확한 Subject·메모리·시점만 멱등 재삭제한다. 노트가 이미 없거나 백업 이후 등록·삭제된 경우도 원문을 되살리지 않는다. 불일치와 누락된 복구 권한은 FAIL CLOSED.
- 복구원장의 승인된 캡처 시각 이후 사건은 포괄하지 않는다. 연속 소스가 입증되지 않거나 이전 스키마인 경우 서비스 재개를 거부한다. 시간별 스냅샷이 연속성 증명이 되는 것은 아니다.
- **운영 DB 적용/공개 기능 활성화/AI 모델 비용·출력/DR Ready 승인은 별개**. 기존 비활성 플래그와 복구 승인 절차는 유지한다.

## 2026-11-11 — 사용자 재확인: 현행 유지·운영 보류 네 가지

사용자가 앞서 제시된 **네 가지 보수적 운영 제안을 모두 승인**했습니다. 이는 기존 허용 범위를 유지한다는 뜻이며, 실모델 실행·캐릭터 추가 공개·운영 배포에 대한 승인이나 기존 미해결 소스 결정의 대체가 아닙니다.

1. **모델·비용:** 기존 DeepSeek API 및 비용 구조를 변경하지 않습니다. 다른 캐릭터의 Provider/model/fallback 선택(O-C1-07), 새 모델 프로필·토큰 제한·가격 등록, 유료 평가 또는 운영 전환을 이 결정으로 승인하지 않습니다.
2. **기억:** 대화에서 자동으로 장기기억을 추출·승인·저장하는 기능은 **OFF**로 유지합니다. 기존 회원 수동 공통 메모리 등록·수정·삭제 방식만 유지하며, SRC-25/SRC-05/SRC-10 및 자동 Memory Proposal 저장 권한은 미해결입니다.
3. **캐릭터:** 이미 개별 승인된 범위만 유지합니다. 미게시/미승인 캐릭터 콘텐츠를 임의로 생성·게시하거나 추가 캐릭터 실사용 대화를 활성화하지 않습니다. SRC-15/SRC-16은 종결되지 않았습니다.
4. **운영:** 실제 운영 백업 복구와 보안 검증을 충족하기 전에는 DB 마이그레이션·API 공개·운영 배포를 하지 않습니다. `MYEONGHA_SHARED_MEMORY_ENABLED=0`, `futureSafePrivacyReconciliation=false`, `drReady=false`를 그대로 유지하며 운영 이슈 #1887·보안 이슈 #1843을 독립적으로 해소해야 합니다.

**효력:** 기존 결정의 재확인이며, 새로운 코드·유료 호출·권한 확대·운영 변경을 허가하지 않습니다. 독립적 승인 및 출처·보안·복구 증거가 필요한 남은 로드맵 단계는 `ROADMAP_IN_PROGRESS`입니다.
