# 명하 Admin Console — 독립 구현 로드맵 v1

> 대상 저장소: `gycha0109-beep/MyeongHa` · 기준: 2026-10-26
>
> **목표:** 1인 운영자가 사용자·상거래·사주/AI·운영 장애·베타 전환을 실제 데이터로 조회하고, 승인된 일부 운영 조치만 안전하게 실행할 수 있는 관리자 웹 콘솔을 순차 구현한다.
>
> **이 문서는 구현 순서표이며, 정책 승인서나 Production 활성화 허가서가 아니다.** 기존 `docs/MASTER_SPEC_INDEX.md`, `docs/P0_DECISION_REGISTER.md`, `docs/AUTH_RLS_PRIVACY_SPEC.md`, `docs/COMMERCE_ENTITLEMENT_SPEC.md`, `docs/ANALYTICS_EXPERIMENT_SPEC.md`, `docs/RELEASE_OBSERVABILITY_SPEC.md` 및 최신 도메인 정본이 우선한다.

## 0. 실제 출발점 (2026-10-26 저장소 확인 기준)

- `apps/admin/README.md`와 `apps/admin/package.json`이 존재하지만, 실행 가능한 관리자 화면·라우트·권한 구현은 이 디렉터리에서 확인되지 않았다. **관리자 앱은 플레이스홀더 상태**.
- `apps/api/src/`에 사용자 범위 읽기, 결제 검증, 크레딧 게이트/원장 후보, Reading, AI 비용 관측·원장 등의 기존 모듈이 존재한다. **코드 존재 ≠ 관리자 접근 계약/Production 사용 가능**.
- `apps/web`에는 사용자 웹 UI가 존재한다. 관리자 UI는 이를 무단으로 수정하지 말고 별도 `apps/admin`에서 구축한다.
- `docs/ANALYTICS_EXPERIMENT_SPEC.md`에는 이벤트와 개인정보 최소화 원칙이 있지만 관리자 대시보드에서 실제 집계 가능한 이벤트 적재·집계가 완료됐다고 전제하지 않는다.
- 사주·결제·원장·개인정보 권한 및 운영 활성화 HOLD는 어드민 작업만으로 해제되지 않는다.
- 본 로드맵 항목은 **모두 착수 전**으로 표시한다. 기존 기능과 중복하는 코드는 각 단계에서 확인해 재사용한다. 확인되지 않은 전체 개발 진행률은 임의 기재하지 않는다.

## 공통 구현 규칙

1. **작은 PR 단위로 실제 구현**한다. 각 단계에서 API/화면/필수 검증까지 연결한 뒤 다음 단계로 이동한다. 별도 장문의 재설계 문서·반복 감사 대신 코드 우선.
2. 관리자 인증·권한은 **서버 측 별도 운영자 신원/허용 목록**으로 검사한다. 일반 사용자 세션, UI에서 숨긴 버튼, 클라이언트 주장, URL 비공개로 관리자 권한을 대체하지 않는다. 사용자 요청용 `subjects.id` 권한과 관리자 권한을 혼동하지 않는다.
3. 브라우저에 DB superuser, `service_role`, PSP/AI secret, 임의 SQL 실행 경로를 노출하지 않는다. 관리자 API는 허용된 읽기 모델과 도메인 명령만 제공하고 **기본 거부**한다.
4. 조회는 최소 필드·마스킹·페이징·검색 속도 제한을 기본값으로 한다. 생년월일시 원문, 대화·기억 본문, Reading 원문, 원본 영수증 및 토큰은 일반 목록·지표·텔레메트리에서 제외한다.
5. 원장·구매·Reading 역사 기록·출생정보·콘텐츠 정본을 DB UI에서 직접 `UPDATE/DELETE`하지 않는다. 보정·환불·중지 등 쓰기는 **기존 검증된 도메인 명령 + 사유 + 감사 이벤트 + 멱등성**을 사용한다.
6. 기존 `OPEN-P0`, `SRC-*`, 출시·판매·Production·PG 활성화 게이트는 그대로 유지한다. 미승인 상품 노출/판매, 유료 Reading 우회, 인연/크레딧 임의 지급, 원가 정책 자동 변경 금지.
7. Owner는 인간 1명이다. 별도 내부 승인자나 운영 책임자를 만들지 않는다. 고위험 작업은 Owner의 행위별 확인과 기술적 감사/복구 경로로 통제한다.
8. 같은 저장소의 결제·사주·UI 트랙과 파일/권한 경계를 지키며 독립 브랜치·PR에서 작업한다. 다른 트랙 CI 때문에 독립 구현을 중단하지 않는다.

## 단계별 작업 목록

### A0 — 관리자 앱 실행 골격 (첫 번째 PR) · P0

- [ ] `apps/admin`에 실행 가능한 최소 관리자 웹 앱, 개발·빌드 스크립트, 타입 검사 및 기존 루트 워크스페이스 연결 구현. 기존 Node/TypeScript/Vite 관례를 재사용하고 새 프레임워크 도입을 최소화.
- [ ] 라우트/화면 골격: `/admin` 대시보드, 사용자, 결제·크레딧, 사주·AI, 통계, 운영 이슈. 실제 기능 없는 메뉴는 비활성 표시.
- [ ] 로딩/빈 결과/접근 거부/서버 오류 공통 상태, 모바일·데스크톱 레이아웃, 실제 운영 데이터가 없을 때 `—` 표시. 모의 수치를 실제값으로 표시하지 않음.
- [ ] 관리자 앱 자체 배포 설정은 기존 환경에 맞춰 **격리된 비공개 진입**으로 준비. 새 공개 Production 배포/운영 secret 투입은 별도 게이트.
- **완료 조건:** 로컬에서 admin 앱 실행 및 빌드, 주요 빈 화면 탐색 가능; 기존 `apps/web` 동작 불변.
- **선행 의존성:** 없음.

### A1 — 운영자 인증 + 안전한 관리자 읽기 API (두 번째 PR) · P0

- [ ] 기존 인증·서버 런타임을 확인하여 Owner만 접근 가능한 관리자 인증/세션 검증 미들웨어 구현. 명시적 관리 권한이 확인되지 않으면 모든 관리자 API와 화면을 거부.
- [ ] 관리자 전용 읽기 API 공통기: 고정된 쿼리·필드 allowlist, 입력 검증, 페이징, 서버측 날짜 범위 제한, 개인정보 마스킹, 오류 코드, 요청 식별자.
- [ ] 관리자 행동 감사 이벤트 기초 구현: actor, action, 대상의 최소 ID, 시각, 결과, 사유(쓰기일 때). 비밀·출생 원문·대화·원본 영수증 저장 금지.
- [ ] 인증 실패, 비관리자, 만료 세션, 타 사용자 자원/임의 ID 요청의 거부 동작만 필수 테스트로 검증.
- **완료 조건:** Owner 이외 읽기 0건, 브라우저로 권한 우회 불가, 운영자 조회 감사 가능.
- **선행 의존성:** A0; 관리자 신원 확정/기존 권한 계약과의 합치.

### A2 — 사용자 검색·상세 조회 (세 번째 PR) · P0

- [ ] 사용자 관리: 내부 subject 참조/가입 상태/가입일/마지막 활동(존재하는 근거에 한함) 검색·필터·페이징.
- [ ] 사용자 상세: 계정 상태, 공개 가능한 사주 Reading 메타데이터, 구매·권한 보유 상태, 크레딧 잔액·거래 이력 요약을 **기존 권한 있는 읽기 모델**로 묶어서 표시.
- [ ] 가입/게스트/병합/삭제 대기 상태는 기존 `subjects` lifecycle 의미에 맞춰 표시. 사용자 데이터 직접 변경/병합/삭제 기능 추가 금지.
- [ ] 조회 결과에서 이메일/연락처/출생정보·민감한 원문 기본 마스킹.
- **완료 조건:** 사용자 검색→상세→관련 내역 진입 가능; 권한 없는 호출은 서버 거부; 페이징 정상.
- **선행 의존성:** A1 및 필요한 기존 읽기 권한·스키마 확인.

### A3 — 결제·크레딧·권한 조회 (네 번째 PR) · P0

- [ ] 결제 목록/상세: 거래 식별자, 상품, 금액, 결제/검증/환불 상태, 시각, 연계되는 entitlement 상태. 검증된 서버 상태만 성공으로 표시.
- [ ] 크레딧 내역: 가용 잔액·지급·차감·만료·복원/보정(실제 원장 스키마가 허용하는 범위), 요청·거래 멱등성 키 연관 조회.
- [ ] 결제/크레딧 불일치 탐지: 검증 성공인데 미지급, 중복 지급 의심, 결제 취소 후 권한 유지 등 **조회 가능한 항목부터 경고**, 자동 수정 금지.
- [ ] 최신 판매 정책과 실제 출시/PSP 게이트를 반영. 크레딧 상품이 유료로 판매 중이라는 가정이나 허위 매출 수치 금지.
- **완료 조건:** 특정 사용자/거래의 지급·차감 원인을 원장에서 확인 가능, 관리자 화면에서 DB 값 직접 수정 불가.
- **선행 의존성:** A1·A2, Commerce/credit 도메인의 실제 읽기 계약.

### A4 — 사주 Reading · AI 실행·비용·오류 관측 (다섯 번째 PR) · P0

- [ ] Reading 운영 조회: 생성 상태, 주제/상품 키, 버전·출처 식별자, 실패 단계, 오류 분류, 전달/열람 가능한 메타데이터. 개인화된 본문은 기본 화면에 노출하지 않음.
- [ ] AI 관측: 호출수, 성공/실패, 토큰, 원화 환산 비용(검증 가능한 환율·단가 기준이 있을 때만), 평균·P95 지연, 재시도, 일별 합계.
- [ ] 캐릭터 대화 응답·사주 해석 비용을 **별도 집계**. AI 원가 연구 목표 **응답당 3~5원, 상한 10원은 미확정 가정**으로 표시하고 달성/실측 수치로 간주하지 않는다.
- [ ] 기존 `seyeon-ai-cost-*`, `postgres-seyeon-ai-cost-ledger-v1.ts`, `security-observability.ts`, `docs/RELEASE_OBSERVABILITY_SPEC.md` 경계를 확인하고 가능한 계측 값만 연결.
- [ ] 모델 호출 원문·프롬프트·출생정보·대화 기록은 일반 운영 로그/대시보드에 적재하지 않음.
- **완료 조건:** 모델/기능/기간별 실제 측정 가능한 비용·실패 현황 조회; 데이터 없을 때 측정 불가로 구분.
- **선행 의존성:** A1 및 실제 AI 비용 수집 경로.

### A5 — 베타 퍼널·채널·품질 지표 (여섯 번째 PR) · P1

- [ ] 기존 `docs/ANALYTICS_EXPERIMENT_SPEC.md`의 이벤트 레지스트리·동의/보존 경계 확인. 필요한 화면/구매 이벤트가 없다면 **레지스트리와 수집 계약을 먼저 승인 가능한 최소 범위로 추가**한 후 수집·집계.
- [ ] 퍼널: 상품 상세 **유효 방문자** → 명식 입력 완료 → 결제 시도 → 서버 검증된 결제 완료 → 결과 열람/만족도. 정의된 동일 기간·고유 방문자 기준으로 분모/분자 표시.
- [ ] 유입: UTM source/medium/campaign 등 원문 PII 없는 캠페인 기준, 직접/검색/소셜 구분. 유입 근거 없으면 unknown 처리.
- [ ] 피드백: 구매 후 1~5점 만족도, 중대 불만 분류, 환불 건수. 환불·중대 불만 비율의 분모와 기간 표시.
- [ ] 베타 승인 목표 **1차 유효 방문 100명, 구매 전환율 ≥5%, 구매 만족도 ≥4.0/5, 환불·중대 불만 비율 ≤10%; 2차 유료 구매자 ≥30명**을 참고선으로 표시. 작은 표본·결측 및 유료/체험단 구분을 함께 표시.
- [ ] 동의/보존 정책 미확정 항목은 실제 비식별 수집 계약이 확정될 때까지 비활성·근거 없음 표시; 무단 추적 도입 금지.
- **완료 조건:** 실제 이벤트로 기간·캠페인별 구매 퍼널 확인, 고객 원문/영수증 등 분석 저장소 유입 없음.
- **선행 의존성:** A1, A3, 현재 analytics 이벤트 가용성과 관련 OPEN-P0.

### A6 — 제한된 운영 조치 (일곱 번째 PR부터, 기능별 분할) · P1

- [ ] **A6-1 크레딧 보정:** 기존 승인된 원장 보정 도메인 명령이 **실제로 구현·허용된 경우에만** 서버 검증/멱등성/사유 입력/행위 확인/감사 로그를 연결. 없으면 UI 버튼 비활성, 별도 Commerce 작업 의존성 기록.
- [ ] **A6-2 환불/철회:** 기존 결제 및 디지털 Reading 환불 정책의 검증된 흐름에서만 상태 조회·기존 처리 진입 제공. 결제 제공자 환불 성공 전 권한 회수/환불 완료로 표시 금지.
- [ ] **A6-3 사용자 조치:** 계정 삭제·사용 제한·복구 등 이미 존재하고 관리자 실행이 승인된 명령만 노출. 원문 직접 변경 기능 추가 금지.
- [ ] 모든 쓰기: 의도 확인 → 서버 권한/명령 검증 → idempotent 실행 → 결과 재조회 → 감사 로그, 실패 시 거짓 성공·부분 적용 은폐 금지.
- **완료 조건:** 안전하고 승인된 조치만 실행 가능; 도메인 명령이 없는 조치는 변경 권한 없음으로 남음.
- **선행 의존성:** A1~A4 + 각 도메인의 기존 승인된 쓰기 계약. 운영 승인 없이 Production 실행 금지.

### A7 — 상품·콘텐츠 운영 및 운영 편의 (후순위 PR) · P2

- [ ] 공지·홈 배너 등 **표현 정보만** 승인된 운영 설정 경로에서 게시·숨김·노출 기간을 조정. 정본 콘텐츠 및 출시 게이트와 분리.
- [ ] 상품 카탈로그와 캐릭터 공개 상태·버전은 우선 읽기 전용. 가격·판매 활성화·캐릭터 설정·Saju semantic authority를 즉시 쓰기 가능한 CMS로 만들지 않음.

## 측정 및 API 구현 원칙

- **관측값/분모:** 매출은 서버 검증 결제·환불 상태를 근거로 하고, 매출 총액/순액을 구분. 구매 전환은 일관된 유효 방문자 기준. AI 응답 원가는 성공 전달 건수와 실제 집계 가능한 비용 범위·누락률을 함께 표시.
- **데이터 출처:** 사용자/권한은 백엔드 소유자 계약, 결제는 검증된 provider/원장 계약, Reading은 provenance 및 entitlement, AI는 cost ledger/telemetry, 분석은 최소화된 analytics event. 서로 다른 상태를 임의 JOIN해 사실처럼 단정하지 않는다.
- **조회 API:** 기존 쿼리·서비스를 감싼 관리자 전용 서버측 adapter. 사용자용 `/api/me` 등을 관리자 목록 API로 우회 재사용하지 않는다.
- **쓰기 API:** 자유 SQL, 공용 `PATCH /table/:id`, 브라우저의 관리자 service key 불허. 기존 도메인별 command만 제한 노출.
- **감사:** 개인정보 원문 대신 actor/action/target reference/reason/request id/result 기록; 삭제·보존 정책은 현행 법무·개인정보 정본을 따른다.
- **검증 최소 세트:** 관리자 아닌 요청 거부, 목록 마스킹·페이징, 결제 거짓 성공/이중 지급 방지 경계, 쓰기 멱등성·감사, 기존 웹 빌드 영향 없음. 추가 회귀 테스트는 실제 변경 범위에 한정.
