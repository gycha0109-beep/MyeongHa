# D4B-10G — 실제 PostgreSQL 연결 정산 종단 간 검증

Watchtower-Track: character-memory

## 목적

기존 D4B-10D는 격리 PostgreSQL의 병렬 임대·정산을 SQL 단위로 검증했고, D4B-10F는 실제 정산 로그인 계정의 권한을 검증했습니다. D4B-10G는 **TypeScript 정산 작업자 → PostgreSQL 연결 → 영속 영수증 확보 → 재구성·정산 → 확인**을 하나의 전체 동선으로 실행합니다.

## 검증

- 매번 파기하는 `myeongha_seyeon_d4b10g_test` 데이터베이스에서만 실행합니다. 정상 사용량과 불명확한 사용량을 각각 승인 시점에 예약한 뒤 실제 프로그램의 최소권한 로그인으로 영수증을 차례로 정산합니다. 잔액은 11100 → 7700으로 변경되어야 합니다.
- 제3의 가상 호출 정산 트랜잭션을 **실제로 확정한 직후에만** 통신 응답이 유실된 상황을 프로그램 연결층에 주입합니다. 프로그램은 성공을 주장하거나 영수증을 확인 처리하지 않아야 합니다. 원장에 정산 확정, 영수증에 미확인 임대가 남아 있어야 합니다.
- 격리 데이터베이스에서만 임대 만료를 앞당겨 새 작업자로 동일 영수증을 다시 처리합니다. 새 AI 호출 없이 기존 정산이 재실행 처리되어야 하고, 점유 예산은 4300에서 변하지 않아야 합니다.
- `CI=true`, 정확한 데이터베이스 이름, 별도 동의된 `SEYEON_DETACHED_REAL_DB_TEST=1` 세 조건이 모두 있어야 검사 본문이 활성화됩니다.
- 운영용 접속 설정 생성기를 사용하지 않고, 별도 PostgreSQL 연결을 첫 명령에서 테스트 전용 최소권한 로그인으로 전환합니다. 테스트 연결은 반환 시 버려 권한 상태가 다른 호출로 넘어가지 않도록 합니다.

실행: `test/db/seyeon_detached_worker_real_driver_end_to_end.sh`, `test/seyeon-detached-worker-real-postgres.test.ts`. 기존 데이터베이스 권한 핵심 검증에 등록했습니다.

## 운영 제한과 잔여 사항

운영 계정 생성, 운영 비밀정보 조회, 실제 AI 호출·유료 비용, 운영 마이그레이션·정산 스케줄러 배포는 수행하지 않습니다. 운영 데이터베이스 이력 불일치 [#1887](https://github.com/gycha0109-beep/MyeongHa/issues/1887)은 별개로 미해결이며, 본 검증 통과로 운영 활성화를 승인할 수 없습니다.

연결 단절, 다중 프로세스 경합, 재시도 안전성은 합성 장애 시나리오이므로 실제 운영의 모든 실패 가능성을 포괄하지 않습니다. 운영 준비 검토에는 별도 실행 환경·최소권한 인증 및 백업 복구 증거가 필요합니다.
