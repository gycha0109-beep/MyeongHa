# D4B-6 — 손님에서 회원으로 전환 중 비용 예약 경합

Watchtower-Track: character-memory

## 목적

계정 전환은 같은 정식 사용자 번호를 유지하면서 손님 접속 증빙을 소모합니다. 하지만 비용 예약은 손님 증빙을 확인한 직후 바로 실행되지 않을 수 있습니다. 이미 확인된 손님 접속 정보가 **계정 전환 완료 후** 비용 예약 권한으로 다시 사용되지 않도록 실제 두 연결이 경합하는지 검증합니다.

## 실제 독립 데이터베이스 연결 절차

1. 기존 합성 회원의 저장 완료된 대화 기록을 일회용 DB에서 손님 이력으로 설정한 뒤 유효한 손님 세션을 발급합니다.
2. 손님 권한으로 합성 비용 3,700을 정상 예약합니다.
3. 연결 A가 전역 일일 예산 행을 잠급니다.
4. 연결 B는 유효했던 손님 증빙으로 손님 식별을 확인하고 비용 예약을 시작하지만 연결 A의 예산 잠금에서 멈춥니다. 데이터베이스 대기 상태를 관측합니다.
5. 별도 연결 C가 정식 회원 전환 명령을 실행해 같은 사용자 번호를 유지하면서 손님 증빙을 소모하고 저장을 완료합니다.
6. 예산 잠금 해제 뒤 연결 B는 **낡은 손님 자격이므로 신규 비용 예약을 거절**해야 합니다. 이를 통과하면 유효했던 과거 증빙만으로 계정 전환 이후 신규 유료 호출을 승인할 수 있는 결함이므로 실패 처리합니다.
7. 회원 신원 확인은 같은 정식 사용자 번호로 연결되며, 새 손님 신원 확인은 거절되고, 기존 예약 비용은 변경되지 않아야 합니다.

## 처리 범위

- 재현을 위한 검증 코드만 작성했습니다. 데이터베이스 함수·권한·운영 정책을 바꾸지 않습니다.
- 검증이 실패하면 **변경 사항 최종 반영과 운영 전환을 중단**합니다. 현재 코드가 안전하다고 미리 단정하지 않습니다.
- 무효화된 손님 증빙 재사용 및 운영 실제 발송은 승인 범위가 아닙니다.
- 한도 및 가격은 모두 합성 값이며, 사용자 정보나 외부 유료 서비스는 사용하지 않습니다.
