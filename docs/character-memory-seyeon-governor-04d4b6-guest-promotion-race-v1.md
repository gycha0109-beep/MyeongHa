# D4B-6 — 손님에서 회원으로 전환 중 비용 예약 경합

Watchtower-Track: character-memory

## 목적

계정 전환은 같은 정식 사용자 번호를 유지하면서 손님 접속 증빙을 소모합니다. 하지만 비용 예약은 손님 증빙을 확인한 직후 바로 실행되지 않을 수 있습니다. 이미 확인된 손님 접속 정보가 **계정 전환 완료 후** 비용 예약 권한으로 다시 사용되지 않도록 실제 두 연결이 경합하는지 검증합니다.

## 실제 독립 데이터베이스 연결 절차

1. 기존 합성 회원의 저장 완료된 대화 기록을 일회용 DB에서 손님 이력으로 설정한 뒤 유효한 손님 세션을 발급합니다.
2. 손님 권한으로 합성 비용 3,700을 정상 예약합니다.
3. 연결 A가 전역 일일 예산 행을 잠급니다.
4. 연결 B는 유효했던 손님 증빙으로 손님 식별을 확인하고 비용 예약을 시작하지만 연결 A의 예산 잠금에서 멈춥니다. 데이터베이스 대기 상태를 관측합니다.
5. 별도 연결 C가 정식 회원 전환 명령을 실행해 같은 사용자 번호를 유지하면서 손님 증빙을 소모하고 저장을 완료합니다.
6. 예산 잠금 해제 뒤 연결 B는 **낡은 손님 자격이므로 신규 비용 예약을 거절**해야 합니다. 이를 통과하면 유효했던 과거 증빙만으로 계정 전환 이후 신규 유료 호출을 승인할 수 있는 결함이므로 실패 처리합니다.
7. 회원 신원 확인은 같은 정식 사용자 번호로 연결되며, 새 손님 신원 확인은 거절되고, 기존 예약 비용은 변경되지 않아야 합니다.

## 처리 범위

- 재현을 위한 검증 코드만 작성했습니다. 데이터베이스 함수·권한·운영 정책을 바꾸지 않습니다.
- 검증이 실패하면 **변경 사항 최종 반영과 운영 전환을 중단**합니다. 현재 코드가 안전하다고 미리 단정하지 않습니다.
- 무효화된 손님 증빙 재사용 및 운영 실제 발송은 승인 범위가 아닙니다.
- 한도 및 가격은 모두 합성 값이며, 사용자 정보나 외부 유료 서비스는 사용하지 않습니다.

## 실검증 결과 — 보안 차단 사유 확인

- 검증 실행: `38072122348`, 데이터베이스 검사 `114271547058`.
- 실제 잠금 경합을 유도한 이후 회원 전환 명령을 확정했습니다.
- 계정 전환 이전에 확인한 손님 요청이 예산 잠금에서 풀리자 **다시 신원을 확인하지 않고 3,700 비용 예약에 성공**했습니다. 해당 호출 번호 끝자리는 `0012`이며, 이는 당초 허용된 예약 `0011`과 다른 신규 호출입니다.
- 검사 출력: `BLOCKER: pre-resolved Guest started a NEW paid call after Member promotion`.
- 따라서 현재는 안전성을 입증하지 못한 단계가 아니라, **구체적으로 재현된 권한 경계 결함**입니다. 합성 호출에만 해당하고 실제 외부 모델 발송은 없었습니다.

## 코드상 원인

- `begin_guest_subject_context_v1`: 손님 세션 유효성을 읽고 현재 거래의 사용자 번호를 지정하지만, 이후 회원 전환과 충돌하는 잠금을 유지하지 않습니다.
- `cmd_promote_guest_runtime_v1`: 손님 세션을 소모하고 같은 사용자 번호를 회원으로 전환합니다.
- `seyeon_ai_lock_active_subject_for_cost_v1`: 실제 예약 시 사용자 행의 `active` 및 미병합 상태를 확인합니다. 손님→회원 전환 뒤에도 두 조건이 참이므로, 이전 **손님 자격 자체가 소멸했다는 사실**을 구별하지 못합니다.

## 조치 결정이 필요한 부분

1. **긴급 봉쇄안:** 실제 서비스에 연결되지 않은 전용 비용 실행 권한에서 손님 자격 확인을 제거하여 신규 손님 비용 예약을 일시적으로 모두 차단합니다. 손님 권한을 쓰는 기존 서비스 경로와 공통 회원 권한은 건드리지 않습니다. 단, 데이터베이스 권한 변경이 필요하므로 별도 승인 전 실행하지 않습니다.
2. **정식 수정안:** 회원과 손님의 예약 권한을 별도 경로로 분리하고, 손님 비용 예약 시 검증된 세션 증빙을 전역 예산 잠금 이후 사용자·손님 세션 순으로 다시 잠가 확인합니다. 원래 손님 자격이 전환으로 소모되었다면 신규 비용 예약을 거절해야 합니다. 기존 일일 전역 예산→사용자→기록 잠금 순서와 정산 재시도 계약을 유지해야 합니다.
3. 손님 정상 예약·전환 전후 경합·손님 증빙 만료·회원 재확인·비용 귀속을 모두 재시험하고 전체 점검을 통과한 후에만 병합을 검토합니다.

**운영 배포·비용 발생·기존 데이터베이스 권한 변경은 이 검증 요청에서 수행하지 않았습니다.**
