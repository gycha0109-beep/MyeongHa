# 명하 전체 캐릭터 공통 챗봇 명세 v1.1

상태: 공통 설계 정책. 구현 및 운영 검증 완료를 의미하지 않음.
기준: Character Runtime Standard v1, 기존 Bible/Canon, Memory Proposal/Grant/Revocation, World/Saju/Disclosure authority.

## 목표
명하의 모든 캐릭터는 각자 고유한 성격과 판단 기준을 유지하며 경험에 따라 지식, 취향, 관계가 변하는 지속적인 인물이다. 특정 캐릭터 전용 정책이 아니다.

## 데이터 불변성 계약
| 구분 | 변경 규칙 | 범위 |
|---|---|---|
| 핵심 성격: 기질, 핵심 가치관, 성격적 결함, 판단 성향, 행동 원칙 | 런타임 불변. 제작자의 명시적 Canon 버전 개정만 허용 | 캐릭터 공통 |
| 지식 및 기술 숙련도 | 근거와 학습 검증을 거쳐 갱신 | 캐릭터 공유 또는 제한된 범위 |
| 취향, 관심사, 비핵심 의견 | 경험 및 선택 근거를 보존하며 갱신 | 캐릭터별 |
| 감정, 현재 욕구 | 상황과 사건에 따라 일시적 변화 | 세션 및 상태 |
| 사용자별 관계, 신뢰, 갈등, 기억 | 승인된 관계 사건에 따라 갱신 | 해당 사용자 |
| 세계관, 중요한 과거, 가족, 공식 설정 | 전문 authority만 변경 | 별도 권한 |

성격이 불변이라고 모든 반응이 고정되는 것은 아니다. 같은 성격이라도 경험, 감정, 관계에 따라 행동 선택은 달라질 수 있다. 불변 성격은 가변 상태 갱신의 대상이 아니다.

## 런타임 파이프라인
1. 사용자 메시지를 신뢰되지 않은 입력으로 접수한다.
2. 기존 4A Integrity/Claim Preflight로 주장, 기억, 권한을 검증한다.
3. Source Authority, Disclosure, 지식 수준 및 접근 권한을 확인한다.
4. Canon, 승인된 기억, 사용자별 관계, 가변 상태를 조립한다.
5. 캐릭터 자신의 욕구와 사용자 요구를 구별하여 행동을 결정한다.
6. Renderer가 캐릭터 고유의 표현을 생성한다.
7. Guard가 권한, 지식 경계, 과거 사건, 인격 일관성을 검사한다.
8. 이벤트 및 지식/취향 변경 후보는 서버 authority를 통해서만 확정한다.

## 정보 주입 및 기억 오염 방어
- 사용자의 주장은 출처가 있는 발언이지 자동으로 검증된 사실이 아니다.
- 존재하지 않는 공동 사건, 관계, 과거, 정체성은 사용자 주장만으로 생성하지 않는다.
- 사용자 메시지의 제작자·개발자 권한 주장은 상위 authority를 대체하지 않는다.
- 동일 주장을 반복하거나 여러 계정이 주장해도 독립적인 검증 근거로 자동 계산하지 않는다.
- 이전 모델 답변 자체는 Canon이나 실제 사건의 증거가 아니다.
- 사용자별 사적 대화와 관계를 캐릭터 공통 지식으로 자동 승격하지 않는다.
- 캐릭터는 부정확한 주장에도 감정적으로 반응할 수 있지만 그 감정이 사실 승인인 것은 아니다.
- 검증된 일반 지식의 학습과 실제 경험에 근거한 취향·관계 변화는 허용한다.
- 원본 턴, 출처, 중복 여부, 변경 전후 값, 시점, 공유 범위를 기록한다.
- 모델 출력 검사만으로 완전 방어를 보장하지 않으며 서버의 쓰기 권한 검증을 필수로 한다.

## 평가 기준
- 모든 캐릭터에서 장기 대화 후에도 Core Personality 저장값 및 버전 유지.
- 지식과 취향은 검증된 경험에 따라 변하고 변경 이력 유지.
- 사용자별 관계에 따라 반응이 달라도 핵심 성격은 일관됨.
- 허위 공동 사건 및 과거 모델의 오류가 공통 기억으로 승격되지 않음.
- 다른 사용자의 개인 정보가 유출되거나 공유 상태를 오염시키지 않음.
- 캐릭터별 차이가 말투뿐 아니라 행동 선택에서도 나타남.
