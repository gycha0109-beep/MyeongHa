# Admin 운영 정책 — 2026-10-27 사용자 확정

이 문서는 단일 Owner가 확정한 관리자 운영 범위의 정책입니다. 기존 로드맵을 대체하지 않으며 운영 DDL·비밀키·배포·고객 조치·추적 활성화의 실행 승인은 포함하지 않습니다.

| 범위 | 확정 정책 | 구현 경계 |
|---|---|---|

| 크레딧 수동 지급·회수 | 고정 업무 수량 한도 없음, 매회 직접 확인 | 기존 PostgreSQL integer 범위·Lot 불변식·음수 가용 잔액 금지·예약 보호·Subject 잠금 유지 |
| AI 월간 예산 | 100,000원, 80%·100% 경고 | Asia/Seoul 달력 월. 확정/추정 분리, 검증 환율 없으면 KRW 미측정, 자동 중단 없음 |

| 부분 환불 | 기존 결제사와 도메인 계약이 모두 지원할 때만 | 미확인/미지원은 서버·화면 모두 비활성. 환불 결과를 추정하지 않음 |

분석 180일과 관리자 감사 365일은 일반 서비스 로그·AI 원문 trace·Commerce 증빙·백업의 보존을 변경하지 않습니다. [기존 개인정보 삭제·보존 정본](ACCOUNT_DELETION_FINALIZATION_POLICY_V1.md)의 열거된 Commerce `P5Y`, 백업 `P30D`, 복원 후 삭제 재조정을 유지합니다. 보정 영수증·배분 원장은 감사 만료 정리 대상에 포함하지 않습니다. 외부 법적 의무에 대한 판단을 이 구현이 대신하지 않습니다.

크레딧 지급 Lot은 `admin_adjustment` 출처를 사용하고 Owner가 확인할 때 만료일 또는 무기한을 명시적으로 선택합니다. 기존 signup/topup/reward 수량·만료 CHECK는 원문 식을 보존하고 신규 출처 조건만 추가합니다. 회수는 현재 가용 Lot에서 기존 만료순 정렬로 배분하고 예약분을 변경하지 않습니다. 미확정 실행 결과는 같은 작업 ID로 재조회하며 새 작업으로 중복 발행하지 않습니다.

분석 확장 이벤트는 `admin-analytics-pipeline-v1` 스키마와 allowlist를 사용합니다. 기존 baseline은 유지합니다. 원문 birth/chat/receipt/token은 수집하지 않으며 쿠키 동의·서명된 탭 세션·서버 검증 성공을 분리합니다. 유효 방문 판정, 동의 문구의 실제 서비스 배치, 삭제 worker 결속과 서버 성공 이벤트 publisher의 실제 연결은 운영 활성화 전에 검증해야 합니다. 보존 기간 확정만으로 수집을 켜지 않습니다. 기존 `SRC-30`의 범용 outbox 실패 재처리 정책을 이 문서로 임의 확정하지 않습니다.

AI 예산 경고 ID는 월·확정/추정 근거·임계값에 결속됩니다. 관리자 화면은 같은 ID의 카드를 교체하여 중복 적재하지 않고 외부 알림은 발송하지 않습니다. Reading 원가·제공사 청구·환율 미연결은 0원이나 확정액으로 대체하지 않습니다.

환불·계정 제한/해제/대리 삭제/복구는 기존 실행 계약이 없는 상태에서 회원 본인의 명령이나 내부 함수를 관리자 권한으로 바꾸지 않습니다. 기존 삭제 작업 상태 조회와 표현 정보 전용 공지·배너 명령은 유지합니다.
