# A4 사전 승인 증명 보존·삭제 정책 — 2026-11-13

**결정권자:** 명하 프로젝트 사용자(단독 Owner).

**2026-11-13 사용자 결정:** 기존 A4 구현·운영 범위와 별도로, 사용자님이 추천된 개인정보 정책(보존 최대 30일, 회원 삭제 연계), 전용 운영 DB·서비스 인증 연결, 비용 상한을 정한 제한적 실제 AI 호출 검증에 동의했다. 상시 비용 수집은 검증 뒤 판단한다.

## 승인된 개인정보 규칙

1. 서명된 A4 준비 증명은 **저장 시각부터 최대 30×24시간** 보관한다. 30일은 최소 보존 의무가 아니라 상한이다.
2. 증명의 **실행 유효기간은 기본 90초(최대 120초)**로, 보존 기간과 다르다. 이미 만료된 증명은 재사용할 수 없다.
3. 회원의 기존 계정 삭제가 시작되어 정본 `public.subjects.status`가 `deletion_pending`으로 바뀌면 **같은 DB 트랜잭션에서 해당 Subject의 증명을 즉시 삭제**한다. `deleted` 변경 시에도 남은 증명을 삭제한다.
4. 증명을 새로 저장할 때 정본 Subject가 `active`인지 잠금과 함께 확인한다. 계정 삭제와 경합해 폐기된 증명이 다시 남지 않게 한다.
5. 별도 최소 권한 정리 역할만 만료 증명을 한 번에 최대 1,000건 삭제하는 함수를 호출한다. 증명 Writer/Reader 및 공개 API에는 직접 삭제·변경 권한을 제공하지 않는다.
6. 기존 개인정보 삭제·보존 정본에 명시된 Commerce `P5Y`, 백업 `P30D`, 복원 후 삭제 재조정은 유지한다. 관리자 감사 365일과 분석 180일을 A4 증명에 무단 전용하지 않는다.

## 시행과 확인 조건

- 변경 대상은 A4 준비 증명 저장소와 전용 서비스 자격증명·접속 경로다. 고객 결제·크레딧·생년월일 원본·사주 풀이 내용은 변경하지 않는다.
- SQL과 코드 병합 자체는 **실제 운영 설치가 아니다**. 만료 정리 일정과 최소 권한, TLS·비밀키·독립 Saju Source DB, 실제 해석 권한의 결속을 확인할 때까지 운영 발급을 활성화하지 않는다.
- 30일 정리 함수만 생성하고 정기 실행을 연결하지 않았다면 실제 **30일 이내 물리적 폐기 완료**를 주장할 수 없다.
- 사용자는 제한적인 실제 호출 검증을 승인했지만 **구체적인 호출 비용 상한·모델·결속·검증 계정**이 입증되지 않으면 호출하지 않는다. 운영 상시 비용 수집은 별도 수용 결과가 나올 때까지 OFF.
- 공급사 실제 호출 전수, 확정 청구·환율 근거를 확보하기 전 `completeCostCoverage=false`, `invoiceReconciled=false`를 유지한다.

## 적용 및 실증 순서

1. 정확한 커밋에 대한 일반 CI 및 필수 통합 검사 성공.
2. 폐기형 PostgreSQL에서 삭제 요청 즉시 제거/재삽입 차단/30일 이전 행 미삭제/30일 이상 만료 배치 정리/Reader·Writer 직접 삭제 거부 검증.
3. 별도 운영 DB에 최소 권한 증명 저장소 설치 후 실제 객체·권한 실측.
4. 안전한 정기 폐기 실행 경로 및 로그 검증, 서버 간 TLS·비밀키 공급 및 Saju 실행 인스턴스 결속.
5. 비용 상한을 확인한 소규모 실호출 이후 독립 공급사 청구 대조. 이상 시 비용 수집을 계속 중단한다.
