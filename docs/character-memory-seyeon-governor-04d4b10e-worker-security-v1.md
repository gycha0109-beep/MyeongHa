# D4B-10E — 분리 정산 작업자 권한·동시 호출 강화

Watchtower-Track: character-memory

## 확인된 결함과 조치

1. 기존 정산 계정 사전검증은 정산 함수 권한을 확인했으나, 신규 영수증 확보·확인·저장 함수의 실제 부여 상태와 원시 영수증 표에 대한 직접 권한은 점검하지 않았습니다. 이제 작업자 역할의 확보·확인 권한은 반드시 허용, 새 영수증 작성과 직접 표 접근은 반드시 차단하며, 로그인 역할이 직접 영수증 확보·확인·작성을 수행하는 권한도 반드시 차단합니다. 항목 하나라도 누락 또는 불일치하면 실행 자체를 거부합니다.
2. 같은 영수증 저장소 인스턴스의 영수증 확보 함수가 동시에 호출되면 첫 번째 데이터베이스 응답을 기다리는 동안 두 번째 호출이 다른 임대를 확보해 첫 임대 토큰을 덮어쓸 수 있었습니다. 이제 DB 요청 **이전**에 프로세스 내부 점유 상태를 설정하고 병렬 요청을 거부합니다. 중복 확인 호출도 막습니다.
3. 별도 정산 작업자에서 영수증을 확보한 후 정산 도중 예외가 발생하면 로컬 상태가 남아 같은 프로세스의 후속 실행이 차단될 수 있었습니다. 이제 실패한 호출의 **로컬** 임대 상태만 폐기합니다. 데이터베이스 임대 토큰과 종료 시각은 건드리지 않아 기존 만료·재실행 차단 규칙을 유지합니다. 정산 성공/실패는 임의로 추정하지 않습니다.

## 검증

모의 데이터베이스에서 필수 권한 각각의 누락·과권한, 같은 인스턴스 병렬 확보, 동일 영수증 중복 확인, 정산 도중 강제 실패 이후 같은 프로세스의 다음 실행을 확인합니다. 실제 데이터베이스의 역할 격리 및 동시 정산은 D4B-10D 검증을 그대로 유지합니다.

이 변경은 서버 내부 연결자와 테스트만 변경합니다. 사용자 요청·응답 인터페이스, 운영 자격 증명, 계정 생성, 유료 모델 호출, 운영 데이터베이스 적용·활성화는 추가하지 않습니다. 운영 전 차단 #1887은 별개로 유효합니다.

## 잔여 사항

정산 작업자가 실제로 실행될 운영 환경과 최소 권한 로그인은 아직 설정되지 않았습니다. 임대 90초 이내 완료가 보장되지 않으면 정산은 중복 청구 없이 보류·재시도되지만 확인은 거부될 수 있습니다. 프로세스 강제 종료 및 실서비스 관찰은 운영 준비 단계에서 따로 검증해야 합니다.
