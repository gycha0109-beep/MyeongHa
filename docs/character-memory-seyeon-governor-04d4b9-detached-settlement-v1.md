# D4B-9 — 만료된 손님 예약의 서버 전용 지연 정산

Watchtower-Track: character-memory

## 문제와 목표

손님 세션이 만료된 **이후에 시작하는 별도 PostgreSQL 작업**은 손님 자격 확인 함수로 정산 권한을 다시 얻을 수 없습니다. 기존 D4B-8B는 손님 자격이 유효한 거래 안에서 정산이 시작돼 그 도중 만료되는 경우에 한정됩니다.

이 변경은 유효한 손님 증빙을 재활성화하지 않고, **이미 비용 예약 원장에 기록된 호출에 한해** 서버 소유 정산을 허용하는 분리된 DB 권한과 호출 함수를 추가합니다.

## 설계

- `myeongha_seyeon_settlement_worker`: 로그인이 불가능한 독립 실행 역할. 일반 API 역할, 기존 AI 비용 실행 역할, 비용 원장 소유자 역할과 멤버십을 공유하지 않습니다.
- `cmd_settle_seyeon_ai_call_detached_v1(subject,turn,attempt,phase,event)`: 오직 이 역할에 실행 권한을 부여합니다.
- 서버 전용 작업자는 **사용자 토큰이 아닌, 서버가 보관한 최초 AI 호출 예약의 정식 사용자 번호·대화·시도·단계·호출번호와 공급자 이용량 응답**을 전달해야 합니다. 직접 DB 호출을 받는 공개 API는 만들지 않습니다.
- 함수는 요청한 사용자 번호로 해당 거래의 읽기 범위를 묶고, 기존 비용 원장에서 정확히 일치하는 유효한 예약이 있는지 확인합니다.
- 일치하는 기존 기록이 없으면 새 예약을 만들지 않고 거절합니다. 일치하면 기존 원자적 정산 함수와 가격·공급자·중복 정산 검사를 그대로 호출합니다.
- 정산 작업 역할은 비용 예약 시작 함수, 일반/전용 손님 로그인 확인 함수, 비용 원장 직접 조회, 예산 행 조회를 사용할 수 없습니다.
- 기존 비용 원장 RLS 정책과 삭제 시 비용 기록 소거 정책은 변경하지 않습니다.

## 독립 PostgreSQL 검증

1. 손님 자격으로 합성 호출 두 건을 정상 예약합니다(각 3,700 microUSD).
2. 손님 세션 만료 시각을 과거로 바꾸고 이전 자격의 새 호출 거부를 확인합니다.
3. 별도 서버 전용 합성 LOGIN에서, 이용량이 확인된 건은 300으로 정산하고 이용량을 알 수 없는 건은 3,700을 보수적으로 유지합니다. 최종 합계 4,000.
4. 동일 사건의 응답 손실·재시도는 기존 결과를 반환하고 금액을 이중 차감하거나 이중 환급하지 않아야 합니다.
5. 다른 사용자 번호·대화·존재하지 않는 호출 번호는 반드시 거부합니다.
6. 작업자 계정이 비용 원장을 직접 읽거나 새 유료 AI 호출을 예약하거나 기존 일반 사용자 실행 역할로 전환할 수 없어야 합니다.

## 운영 적용 전에 별도로 요구되는 사항

**이 변경은 배포·활성화 승인이 아닙니다.** 서버 소유 작업자 LOGIN 발급, 분리된 비밀정보·커넥션 풀, 오직 실제 공급자 응답으로부터 정산 이벤트를 만드는 내부 작업, 큐 소유권·재시도 제한·감사 로그가 필요합니다. 이 작업자는 신뢰된 내부 실행자이므로, 호출 식별자/비용 이벤트를 외부 사용자에게서 그대로 입력받아서는 안 됩니다.

실제 AI 호출, 운영 DB 비밀정보·권한 발급, 비용 정책/한도 변경, 운영 전환은 수행하지 않습니다.
