# D4B-10F — 실제 PostgreSQL 정산 로그인 권한 검증

Watchtower-Track: character-memory

## 목적

D4B-10E는 정산 전용 계정이 가진 **영수증 확보·정산·확인 권한만 허용**하고, 새 영수증 작성·직접 표 접근·외부 AI 실행 권한을 거부하도록 강화했습니다. 그러나 그 당시 신규 필드 검증은 모의 데이터에 머물렀습니다. 이번에는 실제 PostgreSQL 역할과 함수 접근권한이 검사기의 요구와 일치하는지 확인합니다.

## 검증 방법

1. 매번 폐기하는 별도 PostgreSQL 데이터베이스를 생성하고, 운영 코드의 `DETACHED_WORKER_LOGIN_PREFLIGHT_SQL_V1` 상수에 들어 있는 **실제 SQL 문자열**을 추출해 실행합니다. 테스트용으로 동일 이름의 `NOINHERIT` 최소권한 로그인만 만들며, 운영에는 적용하지 않습니다.
2. 검사 결과의 로그인 상태, 소속 역할, 영수증 확보·확인·기록 권한, 원시 원장과 예산표 권한을 기대값과 전체 비교합니다.
3. 다른 AI 실행 역할 전환을 거부하는지 직접 확인합니다.
4. 고의로 로그인에 영수증 작성 권한을 부여했다가 되돌리고, 여분의 역할 소속을 추가했다가 되돌리고, `INHERIT`를 켰다가 되돌립니다. 각 경우 실제 검사 결과가 위험을 감지해야 합니다.

검증 실행은 `test/db/seyeon_detached_worker_preflight_real_roles.sh`이고 기존 격리 데이터베이스 검증 흐름에 포함됩니다.

## 운영 상태

**실제 운영 자격 증명·정산 작업자 실행·유료 모델 호출·마이그레이션·운영 계정 생성 없음.** 운영 데이터베이스 이력 증거 불일치 [#1887](https://github.com/gycha0109-beep/MyeongHa/issues/1887)는 운영 권한 담당자의 별도 조사와 승인 전까지 차단 상태를 유지합니다.
