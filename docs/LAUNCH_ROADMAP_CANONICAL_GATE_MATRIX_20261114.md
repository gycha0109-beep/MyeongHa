# 명하 로드맵 통합 운영 기준 — 최초 출시 / 출시 후 / 트랙 종료선 (2026-11-14)

> **현행 공통 실행 색인.** [제품 소유자 출시 범위 결정](LAUNCH_SCOPE_OWNER_DECISION_AND_TRACK_CLASSIFICATION_20261113.md)을 구현·검증 트랙에 연결한다. 이 문서만으로 코드 활성화, 운영 DB 변경, 결제 판매, 캐릭터 배포, 기존 검사 통과를 선언하지 않는다.
> **우선순위:** 제품 소유자가 최근 확정한 범위 결정 → 해당 영역의 현재 유효한 소스·상품·운영 정책 → 실제 코드·배포·실증 → 당시 로드맵·과거 증거. 서로 모순되면 기록을 삭제하지 말고 후속 결정이 덮는 **정확한 절**을 명시한다.
> **중복 방지:** 여기에는 출시 조건의 *소유 트랙·완료 증거·후속 경계*만 정의한다. 개별 테스트 명세와 상세 개발 이력은 원 소유 로드맵·워크로그에 단 한 번 유지한다.

## A. 최초 웹 **일괄** 공개의 확정 범위

- **사주:** [승인 카탈로그 14개 구매 Offer](https://github.com/gycha0109-beep/MyeongHa/blob/feat/saju-approved-checkout-admission-20261109/packages/contracts/src/approved-saju-catalog.ts) 모두. 단일 9개(원국/기간/관계) + 묶음 5개. 여기서 말하는 '14'는 별도 엔진·연구영역 14개를 뜻하지 않는다. 직접 해석 구성요소는 직업·사업·재물·연애·연운·월운·관계비교의 7개. 묶음은 공유 의미 결과를 재사용하되 주문·권한·구성별 결제/발급 검증이 필요하다.
- **500명 품질 개선:** Saju [활성 7단계·8메뉴 표본](https://github.com/gycha0109-beep/Saju/blob/main/docs/ROADMAP.md)은 **첫 출시 전 필수**. 이것은 승인 Offer 14개나 관계비교 T10의 독립 검증을 대체하지 않는다. 500명이 14개 Offer 모두 구매하는 검사라는 뜻이 아니다.
- **캐릭터:** 세연·라현·백헌·여울·윤호·태겸 **여섯 명의 실제 웹 채팅 동시 공개**. 나머지 서린·미라·도윤은 **이후 공개**. 캐릭터 식별자·과거 9명 전체 세계관은 삭제하지 않으며, 9명 묶음에서만 동작하는 기술 계약은 정식 여섯 명 게시/실행 경로로 변경해야 한다. 기존 5명 방 연결과 윤호 카드 노출만으로 여섯 명 채팅 완료를 주장하지 않는다.
- **Reader:** 구매자가 정식 풀이를 열람·재열람하고 **기본 첫 질문·후속 질문**을 할 수 있어야 한다. **2026-11-14 추가 결정: 최초 공개 6명 모두 Reader를 동시 제공한다.** 각 캐릭터의 Reader 기능은 정식 구매 풀이·개별 권한·서명·Guard/모델 검증이 선행되어야 하며 자동 유료 권한 부여가 아니다. 실제 제공할 Reader×7 구성요소 조합을 명시적으로 지원·미지원으로 판정하되, 기존 9×9 *전체* 조합을 첫 출시에 일괄 필수화하지 않는다.
- **플랫폼:** 웹(모바일 브라우저 기본 사용성 포함) 우선. 네이티브 iOS/Android 앱, 스토어 구매·푸시·실기기 설치를 첫 웹 출시 선행조건으로 사용하지 않는다.
- **출시 방식:** 위 확정 범위 + 실제 운영·안전·계약상 필수 조건이 모두 통과할 때 한 번에 공개. 내부 프리뷰·부분 검증·첫 상품만 판매는 성공 판정이 아니다.

## D. 공통 검증·작업 중복 제거 규칙

1. **영역별 검증 소유자는 한 트랙만.** Saju=계산/해석 의미·서명 원본, Commerce=돈/Grant/환불, Character=게시/독립 채팅·개별 모델, Reader=원본·질문 권한·답변 조회, Security=공통 보안, Ops=운영 DB/복구, Web=실제 브라우저 동선. 다른 트랙은 결과 **연동 시험**만 하며 같은 본문·검사기를 다시 구현하지 않는다.
2. **각 통합 검증은 공유 증거 1건을 참조.** 현재 출처/코드 버전과 정확히 일치하면 재사용; 경로가 바뀌었거나 새 배포였으면 해당 경계만 재검증한다. 무의미한 여러 번의 종합검사나 새로운 플랫폼 시험을 출시 조건에 추가하지 않는다.
3. **품질 검사 오독 금지:** 500명×8메뉴는 Saju 필수 품질; 14개 Offer는 구매/발급 계약; 6명은 채팅; Reader 지원 조합은 실제 제공 집합으로 분리. 하나의 성공을 다른 것의 완료로 승격하지 않는다.
4. **운영 검증의 시점:** 안전 관련 사전 검증(복구 가능성, 취소·권한 회수, 결제·개인정보, 모델 비용/차단)은 필수. 고객 사용 후 발생하는 장기 통계·정기 훈련·고급 성능 최적화는 출시 후 별도 일정으로 관리한다.
5. **상태는 증거 기반:** `계획/구현/격리 검증/운영 검증/공개`를 구분한다. 공통 출시 조건은 전부 `운영 검증` 수준이 필요하며, 판매·배포 시 승인/계약 조건을 추가 확인한다. 과거 문서의 `OPEN`, `HOLD`는 최신 증거로 유지/해소를 판단한다.

## E. 충돌 정정 원장 — 현재 수정·확인이 필요한 것

| 문제 | 현행 해결 기준 | 소유 트랙 |
| --- | --- | --- |
| 9명 'MVP' 출시 vs 최신 6명 | 2026-11-14 제품 소유자 결정으로 **첫 출시 범위만 여섯 명으로 개정**. 9명 전체 장기 저작 목록·기존 권리 보존 | Character |
| 5명 실행/윤호 제외 vs 6명 동시 채팅 | 5명은 당시 PR 기준선. 윤호의 실채팅·실모델·정식 Content Release 추가 필수 | Character/Memory |
| Reader 9×9 전체 vs 기본 질문 | 실제 제공할 Reader×제품 구성표(지원/미지원)를 검증. 9×9 *전체*를 최초 출시 강제하지 않음 | Reader |
| 1/11/12/14개 상품 숫자 혼재 | **14개 구매 Offer, 7개 의미 구성요소, 기존 12개 표시 주제, Saju 8개 품질 메뉴**를 서로 다른 차원으로 기록 | Commerce/Saju/Web |
| 세연 우선 Preview vs 여섯 명 일반 채팅 | 과거 프리뷰 이력을 보존하되, 6명 정식 일반 채팅 동시 공개 요구가 우선. 6명 모두 기본 Reader 제공(각 캐릭터별 별도 권한·모델·근거 검증 필수) | Character/Reader |
| 출시 후에 해야만 관측 가능한 지표 vs 출시 필수 안전 검사 | 사전 검증과 사후 상시 관측을 분리. 사용자 500명 사주 품질 검증은 이 범주와 관계없이 **출시 전** | Security/Ops |
| 일부 로드맵의 모든 단계 완료=서비스 출시 | 독립 트랙 완료·상품별 준비·전체 일괄 공개를 분리. 확정된 14+6+Reader+500명+운영 필수는 축소 불가 | 전체 |

**갱신 규칙:** 발견된 실제 충돌은 원 소유 로드맵의 *현행 실행 섹션*을 수정하고, 과거 실행 기록은 `historical` 표기 아래 보존한다. 불필요한 내용 반복은 이 색인을 링크로 대체한다. 이슈·기능 플래그/테스트가 실제로 옛 기준을 강제하는 경우, 소유 트랙에서 **구현과 검사 정합성까지 수정**해야 하며 문서 정정만으로 블로커 해소라 보고하지 않는다.

## F. 전체 출시 준비 판정

- 모든 승인 Offer 14개 구매·발급·보관/Reader·환불 E2E
- Saju 500명 7단계, T9 기간/의미, T10 3상품 고객 풀이·발급 완료
- 여섯 명 각각 정식 게시·독립 채팅·모델/Guard/예산·실사용 E2E
- 구매 풀이의 보호된 첫·후속 질문 및 실제 활성 Reader 조합 검증
- 운영 DB/복구/인증/개인정보·상업 호스팅/실제 PortOne 계약·법적 고지와 웹 공개 수용
- **최초 출시 시점** 사전 필수 검증 PASS / **이후** 모니터링·정기 훈련 계획 및 실제 수행 경로 준비

위 상태를 모두 검증한 경우에만 `WEB_LAUNCH_READY` 여부를 판단한다. *이 문서 정리 또는 개별 트랙 `ROADMAP_COMPLETE`가 자동으로 이를 결정하지 않는다.*
